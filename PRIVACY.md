# Privacy

Flare has no accounts, no analytics, no telemetry and no crash reporting. It keeps your settings, open tabs and a diagnostics log on your own PC (`%APPDATA%\Flare`), and nothing about you or what you do in it is sent anywhere.

## The diagnostics log

To find out why the app froze or failed, Flare keeps a log on your PC (`%APPDATA%\Flare\logs`, at most 10 MB, the oldest part removed as it grows): when the window or the app was slow and for how long, errors and panics, and a timeline of what you did in the app (a tab opened, closed or switched, a Settings page, an update, dictation starting and stopping, a shell starting and ending), and what each tab's agent indicator showed and why (states such as working or finished, never what is on the screen, in a title or in the conversation), and what went wrong in a browser panel (a page refused, a pop-up, a page that failed to load, a certificate error, a denied permission, a browser process that failed, and in the detailed mode the sites a page passed through). For a web page it keeps the site's name only (such as `bank.example`), never the address, its path or query, the page's title or text, form data, cookies or a certificate. Folder paths are written in full. What you type, what you copy, what you say and what a program prints on the screen are never written to it. The log is **never sent anywhere**; it leaves your PC only if you send it yourself. Settings > Diagnostics opens its folder, and has a switch for more detail.

## What reaches the network

Flare makes **no request on its own** in this version. The update check is built but switched off until the project is public; this file changes in the same release that switches it on.

Everything else happens **only when you ask for it**:

- **Installing an update:** not available yet. When it is, clicking Install downloads that release's installer from GitHub.
- **Dictation** (off by default): turning it on and choosing a model downloads the speech engine from whisper.cpp's GitHub releases and the model from Hugging Face; the optional NVIDIA acceleration pack is a separate download you choose. Each file is checked against a fixed SHA-256 before use. Your voice never leaves the PC: it goes to a speech engine running on your own machine (127.0.0.1, or straight into the engine's input for the Parakeet model) and is never written to disk.
- **Links:** clicking a link printed in the terminal opens it in your browser. Nothing is opened or fetched before you click.
- **Web panel:** a page you open in the panel beside the terminal (by typing its address, or because Claude asked for it) is loaded by Microsoft's WebView2, the engine of Microsoft Edge, so the page and whatever it loads reach the network exactly as in a browser. The panel has its own profile folder (`%APPDATA%\Flare\WebView2`, under your Flare profile, never Edge's), which keeps that site's cookies and cache on your PC, and the passwords and form entries you choose to save there (the browser offers to save a password when you sign in, and fills it in next time; they are stored by WebView2 in that folder, encrypted for your Windows account, never shared with Edge or sent by Flare). That folder is under your profile, so uninstalling Flare does not remove it: delete it yourself to sign out of every site at once. A test or second copy of Flare started with its own profile has its own panel folder, so Flare and FlareStable keep separate logins; it opens only http and https addresses, denies every permission request a page makes (camera, microphone, location, notifications) and lets a page open no window of its own; a download is held until you answer Flare's own "Save this file?" question, and only then does the browser save it into your Downloads folder. WebView2 may contact Microsoft the way Edge does (for example SmartScreen's check of an address), which Flare does not control. Flare itself sends nothing about the pages and keeps no history beyond the address each tab's panel last showed (in `panels.json`, so it comes back with the tab). When an agent in that tab uses the page (`browser_look`, `browser_click` and the other `browser_*` tools), what the page shows (a screenshot and a list of its text and controls) is handed to that agent, a program that is already running in your terminal and that sends what it reads to its own service, as it does with any file it opens; Flare itself sends nothing. The agent can use only its own tab's panel, a ribbon says so while it does, your own click or key in the page stops it, and it cannot run scripts in the page unless you switch on "Let agents run scripts in pages" in Settings (off by default). **Mini-apps:** when Claude shows you a page it wrote (`show_html`) or a diagram (`show_diagram`), Flare writes that page into a folder under `%APPDATA%\Flare\apps`, shows it in the same WebView2 engine but in a private browser profile of its own that keeps nothing (no cookies, no history, nothing shared with the web panel or with Edge), and removes the folder when you close the panel, when another panel replaces it and at the next start. The page can make no request that leaves your PC: a policy written into the page, and a second check in Flare, stop it, unless Claude asked for the network and you switched on "Let mini apps use the network" in Settings (off by default), which lets it load `https` content only. The diagram drawing code (Mermaid) is part of Flare and is never downloaded. If the WebView2 Runtime is missing, the panel shows its download page's address and a button, which opens it only when you click. **Mods:** a mod is a folder in `%APPDATA%\Flare\plugins`, put there by you or by Settings > Plugins from a `.zip` you choose (Flare never fetches one by itself, see "Installing a plugin" below); it does nothing until you turn it on in Settings > Plugins, which first shows what it may do. A mod's panel is shown in the same engine in a browser profile of its own that keeps only that mod's own data on your PC (for example the notes the sample mod keeps), apart from the web panel's and Edge's; its page is served from the mod's folder by Flare and can make no request that leaves your PC. A plugin you turned on with the `network` permission ("Use the internet") is the one exception: its pages can load from and send to public `https` addresses (never plain http, and never this PC or your local network: loopback, private addresses and local names are refused), from a browser folder of its own (`%APPDATA%\Flare\WebView2-plugin-net`). Every connection of those pages, and of a mini-app with the network on, goes through a small relay inside Flare, on `127.0.0.1` only: it looks the name up itself and connects only to a public address, so a public name that leads to this PC or your local network reaches nothing there; it adds nothing, keeps nothing and sends nothing of its own; what it sends is that plugin's doing, which is why Settings warns when it may also read your sessions or tabs. When Claude plays a sound with `show_audio`, a file is copied into a mini-app folder like a page and played there; an address must be public `https`, and only that sound is loaded from it. When Claude shows a 3D model with `show_model`, the file is copied into a mini-app folder the same way and read there, with no network; the viewer code (three.js) is part of Flare and is never downloaded. A plugin you turned on with the `process` permission ("Run its own program on this PC (full access)") is the other exception: Flare starts the program that came in its folder, which runs as you with your full access, so it can reach the network and your files as any program you run can (Settings says so before you turn it on, and it is stopped when you turn the plugin off or close Flare); what it prints is kept on your PC in `%APPDATA%\Flare\plugins-logs` (about 2 MB at most per plugin). A mod can only do what its permissions say, and a mod you turn off is stopped at once. When Claude calls a mod's tool, the text Claude sent goes to that mod's page, and what the page answers goes back to Claude, a program already running in your terminal; Flare itself sends nothing. **Filling logins:** a plugin you turned on with the `fill` permission ("Fill logins into your web panel"), such as a password manager's, can ask Flare to type a saved login (a user name, a password, a one-time code) into the web page in a tab. Flare first checks that the page belongs to the login's own site, then asks you in its own dialog, and types only after you click Allow; the login goes from the plugin to that page and nowhere else: never to the agent, and never into a Flare log, setting or file (the log line of a fill names the plugin, the page's host and whether it was filled). The same plugin can ask you for a secret, such as its master password, in Flare's own masked field; what you type goes to that plugin only, and Flare neither keeps nor logs it. What the plugin then does with it is that plugin's doing, which is why Settings warns when it may also use the internet.
- **Installing a plugin:** in Settings > Plugins you can install a plugin from a `.zip` file on your PC or from an `https` address you paste. Only when you press Install (or Update, for a plugin installed from an address) does Flare download that one file: at most 50 MB, within a minute, with no cookies and not through the web panel, following at most 5 redirects, each again `https` to a public host (never this PC or your local network). The address is kept with the plugin in `mods.json`, so Update knows where to look. The plugin is installed off, and nothing in it runs until you turn it on.
- **Live preview and notifications:** when a tab prints the address of a local site (`localhost`, `127.0.0.1` or `[::1]` with a port), Flare looks in Windows' own list of listening ports to see whether something is serving it, and shows a Preview chip; it never connects to that port itself and never reaches a name that is not on your PC. The chip loads the page, in the web panel above, only when you click it (Settings > Terminal > Links turns it off). When an agent in a tab you are not looking at asks you a question, Flare asks Windows to show a notification with the tab's name and the question; the text goes only to Windows' notification centre on this PC (Settings > Agents turns it off). Windows keeps notifications in its own history, and may show them on a linked phone if you set that up, which Flare does not control; turn the setting off if questions may contain sensitive text.
- **Sonara** (the text-to-speech reader for Claude Code, if you run it): when Claude Code's question widget in a tab changes question, Flare tells the Sonara running on your own PC (127.0.0.1, at the address and with the key in Sonara's own `runtime.json`) the question showing and a random id of that tab, so Sonara can read the question you moved to. Without Sonara nothing is sent. Each tab's shell carries that id as `FLARE_TAB_ID`.
- **Remote sessions** (a tab that runs on your other machine): only when you open such a tab, or one comes back with your tabs, Flare starts your own `ssh` to the machine you listed in `machines.json` in your profile, with your own ssh settings and keys, and runs `flare --serve-remote` there. No password is asked and no token or environment of this PC is sent. Over that link go only what the tab needs: what you type in it, what it prints, its size, and, so this PC can show its marks and its conversation, the other machine's words for the tab (working, a question and its text, finished or failed, the agent, its Claude session id, folder and title) and what is said in its Claude session. Files cross only when you ask: a file link you click in the tab brings that one file from the other machine (only from the tab's folder or that machine's temp folder) and keeps a copy in this PC's temp folder until the tab closes; a file or a folder you drop on the tab, or copied files or a picture you paste there, is copied to that tab's own folder in the other machine's temp folder (removed when the tab closes), and its path there is pasted into the tab. No path of this PC is sent. When the tab prints a local server address (`localhost:5173`) and you click its Preview chip, Flare starts your `ssh` once more, as a tunnel from a free port on this PC's loopback (127.0.0.1 only) to that port on the other machine, and the side panel shows the page through it; the tunnel ends when the chip goes or the tab closes. The machine that runs a session holds off its own sleep while a session someone follows from the other machine is working (the display still sleeps and the screen still locks), and sleeps as usual once none is. Nothing else is sent, and no third party is involved: it is your ssh between your two machines. **Computer sharing** (Settings > Machines > This computer) is off until you turn it on. Turning it on lets your other computers reach this one over SSH on your home network: on Windows, after the system's permission prompt, Flare turns on Windows' own SSH server (Windows downloads it from Windows Update when it is missing) and opens it and Flare to private networks only, never with password logins turned on by Flare; on a Mac it turns on Remote Login (macOS asks for your password first). To see whether that server already runs, Flare looks at this computer's own port 22 (127.0.0.1 only). Nothing is sent anywhere by turning it on. Turning it off removes the keys Flare added and offers to stop the server if Flare started it.
- **What you run:** the terminal runs your own shell, and whatever you run in it reaches the network as you tell it to.

## What it adds to Claude Code

Flare adds a small local plugin, `flare-status`, to the Claude Code sessions started in its tabs, so the tab can show what the agent is doing: working, waiting on you, finished or failed. The plugin's hooks print one fixed line (`OSC 777;flare-agent`) into that tab's own terminal; they send nothing over the network, read nothing, and write no file. It is passed through an environment variable of the tab's shell, never written into your Claude Code settings. Settings > Appearance > "Exact status from Claude Code" turns it off for every terminal opened afterwards.

## What programs in a tab can do

A program running in a tab (Claude Code's /copy, or anything you reach over ssh) can put text ON your clipboard with the standard OSC 52 sequence, up to 1 MB, and a "Copied" badge shows when it does. Nothing in a tab can READ your clipboard that way: such a request gets no answer. The text a program copies is never written to the diagnostics log. When a program asks, the terminal also tells it its own name and version (XTVERSION, `Flare <version>`) and the colours it is painted in, so it can draw to match; that answer goes only to the program that asked, on your PC.

## Dictating from any app

Dictation (off by default) can take your voice with another app in front. With **Dictate from any app** on (it is on by default once dictation is on; Settings > Dictation turns it off), Flare watches the keyboard for the dictation key only:

- **What the keyboard hook reads.** A Windows keyboard hook inside Flare looks at the keys of your dictation key and nothing else. It learns that one of those keys went down or up, and the number of the window in front when it did. While one of them is held it learns only that some other key went down, never which key. While the Claude session picker is open it also reads the digits 1 to 9 and Esc, and only those, and it passes every other key on untouched. It types nothing and writes nothing about the keys.
- **Between copies of Flare.** Copies of Flare on this PC talk over a local named pipe that only your Windows account can open. Two copies first prove they hold the same key: 32 random bytes in `%LOCALAPPDATA%\FlareDictation\link.key`, beside the speech models, made once and read by every copy. Over that pipe the copies exchange the names and folders of their open Claude tabs and, when you pick one, the words you dictated. Nothing goes over the network.
- **Where the words go.** Into a Claude tab's terminal, as a paste. In a shell that is not running Claude, dictated text is pasted and never sent with Enter. In a running Claude prompt, Flare presses Enter once, and only after it has checked that tab is still the one you picked and still runs Claude.
- **What is kept.** The window's number lives in memory for that one dictation. The keys, that number, the words and the audio are never written to a file, never put in the diagnostics log (which keeps only the phases: listening, transcribing, pasted) and never sent anywhere.

The speech models are in `%LOCALAPPDATA%\FlareDictation`. When you first switch dictation on, Flare links any of the same models that another dictation app on this PC already holds in its own folder, after checking each one's size and SHA-256, and it never writes into that folder.

If the app ever gains a request that is not listed here, this file changes in the same pull request.

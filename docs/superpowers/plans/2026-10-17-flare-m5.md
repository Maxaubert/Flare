**Goal:** Everything that lets a person work with what is on the terminal screen and move text and
files in and out of it: mouse selection (character, word, line, block; drag with auto-scroll;
shift-extend), copy (Ctrl+C by physical key, the "Copied" badge, a program's own selection, OSC 52),
paste (Ctrl+V, Ctrl+Shift+V, right-click Paste: bracketed, sanitised, copied files as quoted paths,
an image as the agent's one image key), file drop (typed quoted path, never Enter), Backspace over a
selection, the click-to-caret rule, mouse reporting for programs that own the mouse, find in
scrollback (the find bar exactly as Prism Terminal draws it, next and previous, highlight all, the
count, wrap-around), links (web, OSC 8 and existing paths: painted, hovered, clicked, opened through
the allowlist), the IME caret hold, and the terminal right-click menu. All of it at every display
scaling from 100% to 300% on both renderers. Every Prism Terminal v0.55.6 unit test that
`docs/test-port.md` maps to these areas and that M2 did not port is ported as a Rust test (ledger in
Appendix A); every `docs/parity.md` line of section "M5" is answered in Appendix B.

## Global Constraints

Copied from the roadmap and M2/M3; every task obeys them.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes** anywhere (code comments,
  docs, test strings, UI copy); CI greps for them.
- Flare's own names only; never a Prism name in an identifier, path, key or string (README and docs
  may name Prism Terminal as the source). Setting keys `flare.*`.
- **Every display scaling works** (roadmap, owner 2026-10-17: 100, 125, 150, 175, 200, 225, 250 and
  300 percent, both renderers, moving between monitors). For this milestone: every hit test, every
  highlight rectangle, every outline, the find bar and the badge are computed in whole device
  pixels; borders and outlines are `max(1, floor(scale))` device pixels (the Chromium rule Prism
  Terminal's `1px` obeyed, M3 Verified facts); every geometry test runs at the eight scales
  `SCALES = [1.0, 1.25, 1.5, 1.75, 2.0, 2.25, 2.5, 3.0]`; the screenshots cover the whole matrix
  (roadmap: "every UI milestone screenshots that matrix"): every scene at all eight scales on the
  software renderer and the three key scenes at all eight on the GPU (Task 27); Opus reads 100, 150
  and 225 of every scene zoomed and the other five scales of the key scenes.
- **Security (roadmap Review Focus, rules 1, 133, 135):** what reaches a shell is inert until the
  user acts. Pasted text passes `sanitize_paste` (no ESC, no C0 other than TAB LF CR, no DEL, no
  U+009B); dropped and pasted paths pass `quote_paths` (a refused path types nothing); a drop never
  types Enter; a click never runs a program (allowlist, rule 134); OSC 52 is write only; the
  clipboard text is never logged or sent anywhere.
  - **The quoting shell is the shell that RUNS, never the one the tab asked for.** A path quoted
    for PowerShell and typed into cmd is NOT inert (`'C:\a&calc.txt'` runs `calc.txt'` in cmd).
    Every `PathShell` comes from `path_shell_of(handle.shell_id())`, the id the session was
    actually spawned with (Task 16e adds the getter); while it is `None` (shell not started) a
    drop and a copied-files paste type NOTHING (text paste is unaffected).
  - **A path is opened only through `open_term_path(base, text, ..)`**, which re-resolves the text
    and applies the allowlist (rule 134, O22). No code in M5 hands a path from the UI straight to
    `PathOpeners::open_path`; `base` is the folder `PathLinks::find_path` reports
    (`PathFound.base`), and the `cwd` handed to `PathLinks` is the tab's local folder after
    `folder_after_report` (rule 133: a UNC folder from an OSC 9 report is never statted).
  - **A url is opened only after `is_web_url`**, and `flare_win::shell_open::open_url` refuses
    anything but http(s) again.
- **UI thread never waits (rule 34):** reading and writing the clipboard, statting paths and opening
  files run on worker threads and answer with a message; the one bounded exception is the program
  copy watch's read (8 ms cap, Task 21). Any blocking call in non-test code carries `// sync-ok:
  <reason>` on the same line; M2's `tests/sync_calls.rs` scan covers `flare-term`.
- **Typing is heard from keys (rule 9):** a mouse report, an OSC 52 write and a reply never mark the
  tab as typed; a paste, a dropped path, a selection delete and a click-to-caret do (PT `markTouched`).
- No new dependency. Every `pub fn new() -> Self` with no arguments also gets `impl Default`.
- CI gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo nextest run --workspace`, `cargo deny check`.
- Nothing in tests may open a visible window, take the foreground, touch the real clipboard or the
  real `%APPDATA%\Flare`. Clipboard tests use `MemoryClipboard`; tests that need a folder use
  `tempfile`; tests that start a shell reap it (M2's `Guard`); UI tests use the headless software
  platform (M3's `Harness`) only. A test never calls `ShellExecuteW`: openers are fakes.
- Builders: Haiku by default, Sonnet where marked. Reviews: Opus. Never Fable.
- The PR reports test counts, the screenshots (Task 27) and the Opus findings.

## Review Focus

- **Hostile paste and drop** (Tasks 8, 21, 22, 25): text holding `ESC[201~`, other controls, mixed
  newlines; a file named with quotes, `$(...)`, `%`, `!`, `&`, or an ESC; a cmd tab (also one
  started with no explicit shell id while cmd is the default); a WSL tab. Nothing can end the
  bracketed paste, no drop or path paste runs anything or types Enter. A multi-line TEXT paste into
  a shell that did not ask for bracketed paste (cmd) delivers its lines as typed, exactly as Prism
  Terminal and xterm do (D15); the roadmap's "multi-line ... inert until the user acts" line is
  therefore met only for bracketed shells, and Question 4 puts that to the owner. Opus reads the
  byte log of the fake pty in the Task 25 tests, not just the assertions.
- **Selection correctness on cells, not characters** (Tasks 3, 4, 5, 6, 16a): wide characters, emoji,
  wrapped lines, scrolled-back views, the 10,000-line cap. Every boundary is a cell boundary; the
  text comes from one cell-to-text function (rule 21).
- **Display scaling** (Tasks 2, 15, 17, 18, 27): the highlight rectangles tile cells exactly, the
  outlines and underlines are whole device pixels, the find bar and the badge edges are crisp at 100,
  150 and 225, the pointer lands on the right cell at every scale (`hit_cell` at the eight scales).
- **No pass holds the UI** (Tasks 12, 13, 23): find over 10,000 lines of scrollback and the link
  scan run in slices of at most 8 ms; link scanning is viewport-only; the count job yields.
- **Keys** (Tasks 23, 24): while the find input has focus every key goes to it except app chords;
  Ctrl+F is the program's in a full-screen program (alternate screen OR mouse tracking, which M3's
  `KeyContext` did not yet cover); Ctrl+C by physical key; one Ctrl+V is one paste.
- **Mouse ownership** (Tasks 7, 23): a program that asked for the mouse gets press, release, motion
  and wheel reports; Shift gives the selection back; a right click still opens the menu; nothing the
  program is sent marks the tab typed.

**xterm.js behaviour Prism Terminal has (read in the sources):**
- Word separators (`OptionsService.ts`): `' ()[]{}\',"`'`, i.e. space ( ) [ ] { } ' , " and backtick.
  A word is found by `_getWordAt`: the clicked cell is always in the word; the scan goes left and
  right over cells that are not separators (a wide character's spacer is never a separator); a click
  on a space selects the run of spaces (double click only; right click passes `allowWhitespaceOnly
  = false`). A double click on a link selects the whole link first.
- Selection mode by modifier (`shouldColumnSelect`, `shouldForceSelection`): on Windows Alt+drag is a
  column (block) selection; with a program holding the mouse, Shift forces a selection; a Shift
  press with a selection extends its end (`_handleIncrementalClick`); click count 1 starts, 2 selects
  the word, 3 selects the line (the logical line across wraps); further counts do nothing.
  Coordinates use half-cell rounding for selections, so a selection is between cell boundaries.
- Drag past the viewport (`_getMouseEventScrollAmount`): `offset` is the distance beyond the screen
  in CSS px, clamped to +-50, divided by 50, `amount = sign + round(offset * 14)` (JS `Math.round`),
  a timer every 50 ms scrolls by `amount` lines and sets the selection end to the last (or first)
  visible row, column `cols` (or 0) unless it is a column selection.
- Selection text (`selectionText`): rows are `translateToString(trimRight)`, wrapped rows are joined
  to the row above without a break, non-breaking spaces become spaces, rows are joined with `\r\n`
  on Windows; a column selection takes the same columns of every row and returns "" for zero width.
- Selected cells are drawn with the theme's selection colour made OPAQUE over the theme background
  (`selectionBackgroundOpaque`), also when the terminal is not focused unless
  `selectionInactiveBackground` is set (Prism Terminal sets neither). An opaque colour is blended at
  0.3 opacity first (`ThemeService.ts`). Prism Terminal's selection colour is the theme's `selection`
  or the cursor colour at alpha 0x55 (`termTheme.ts`: `selectionBackground: ${cursor}55`).
- Mouse protocols (`MouseStateService.ts`): X10 = press only, no modifiers; VT200 = press, release,
  wheel, no motion; DRAG = those plus motion while a button is down; ANY = everything. Event code =
  button (left 0, middle 1, right 2, none 3) + shift 4 + alt 8 + ctrl 16 (+ 32 for motion); a release
  is reported as button 3 except in SGR. Default encoding: `ESC [ M` then three bytes `code+32`,
  `col+32`, `row+32` with 1-based col and row, NO report when any byte would exceed 255. SGR:
  `ESC [ < code ; col ; row` then `M`, or `m` for a release.
- Search addon: case-insensitive literal search by default (Prism Terminal passes no option),
  wrapped lines searched as one string, `findNext` starts from the terminal's current selection:
  AT its start with `incremental: true` (Prism Terminal passes it while TYPING, `TermFind.tsx
  onChange`) and just after its end without it (Enter, the buttons); `findPrevious` is always
  called with `incremental: false`. Flare maps this as `same_term = !incremental` with `prev` = the
  active match (or, when no match is active, a zero-size match at a standing selection's start). It wraps
  around, selects the match and scrolls only when it is outside the viewport (the match goes to the

## Decisions taken by the planner (not the owner)

D1. **Selection is stored in alacritty's `Term::selection`** (type `Simple` or `Block`), written
   from cell boundaries and read back through `to_range`. This gives scroll rotation and resize
   handling for free. Word and line expansion, text extraction, the half-cell rules and the
   drag-scroll are Flare's own ports of xterm's (`word_at`, `sel_machine`, `sel_text`), because
   alacritty's `Semantic` and `Lines` expansions and `selection_to_string` differ from xterm's.
D2. **Known divergence, reported to the owner (Question 1):** alacritty clears a selection when the
   program erases lines it touches (EL, ED) and on a column-count resize; xterm.js kept it. A
   selection in the scrollback is unaffected; a selection on the live screen of a program that
   redraws (Claude Code's inline renderer) can vanish while it streams. The test
   `an_erase_over_the_selection_clears_it` documents it. Fixing it needs a scroll counter alacritty
   does not expose; it is left for M10 unless the owner wants it earlier.
D3. **A boundary model:** every selection end is a cell BOUNDARY `b` in `0..=cols` of an absolute
   row (`Anchor { row, b }`), converted to alacritty as `column = b` with `Side::Left`, or for
   `b == cols` the last column with `Side::Right`. A wide character is entered as a whole: over
   either of its two cells a pointer in the first cell means the boundary before it, in the second
   the boundary after it.
D4. **Find is Flare's own literal search** (case-insensitive by default, `case_sensitive` a field
   that no control sets: Prism Terminal's bar has no case button, so neither does Flare's; adding
   one is a Question). It runs on logical lines from `cells.rs` so wide characters, wraps and the
   alternate screen are right, and counts in slices (`scan_plan`).
D5. **Links are scanned for the viewport only**, each frame that is dirty, with a per-logical-line
   cache keyed by the rows' text, the OSC 8 spans, the ink and the folder (Prism Terminal's
   `lineKey`). The grid is drawn from a snapshot every frame, so a scrollback link needs no stored
   decoration and the 8 ms sliced scrollback pass is only needed by find's count (Task 12a ports
   `sliceRows`, and its 8 tests, as `flare-term/src/scan_plan.rs`).
D6. **A link opens on a plain left click**, as Prism Terminal (parity.md "Left click opens a link",
   two-apps #95). The brief for this plan said "path links with Ctrl+click"; Prism Terminal does not
   require Ctrl for any link (Question 2). The rule lives in one function, `link_click_needs_ctrl`,
   which returns `false`; flipping it for paths is one line and one test.
D7. **Copy-on-select does not exist in Prism Terminal** (a search of `PT/` for it found nothing; xterm
   has none). Flare has none.
D8. **Alt+click moving the cursor** (xterm's default `altClickMovesCursor: true`) is NOT ported: Prism
   Terminal's plain click-to-caret (`click_caret.rs`, M2) is the owner's feature; an Alt+click with no
   drag selects nothing. Recorded in `docs/features.md`.
D9. **Right click selects nothing** (xterm's `rightClickSelectsWord` is a Mac default), and always
   opens the menu, also in a program that owns the mouse (Prism Terminal's `contextmenu` handler
   ignores mouse mode); the press is still reported to a program that asked, as xterm does, unless
   a selection exists (xterm `handleMouseDown`).
D10. **An empty cell and a typed space are the same** to the buffer adapter (alacritty stores a
   space for both). A prompt's trailing space is therefore not "printed text" for `text_end`
   (click-to-caret end and selection trimming). Recorded in `docs/features.md`.
D11. **Mouse reports are bytes, not typing:** `TermHandle::write_report` writes without marking the
   tab typed and without snapping the view.
D12. **The clipboard is a port** (`ClipboardPort`): `WinClipboard` in production, `MemoryClipboard`
   under `--e2e` (the in-memory stand-in rule) and in every test. Reads and writes run on a worker;
   only the program-copy watch reads with a bounded 8 ms wait.
D13. **Image and newline keys move from M6 to M5:** `image_paste_key` and `newline_key` (and their 5
   tests) are ported into `flare-agent/src/keys.rs` now, because paste and Shift+Enter are wired
   here. M6 only supplies the agent kind (`AgentView`, default "no agent").
D14. **`TermHandle::paste` gets the xterm newline rule** (`\r\n` and `\n` become `\r`) via the new
   pure `paste_bytes`, so every caller (this milestone, M8's dictation) is right.
D15. **No multi-line paste confirmation** and no "paste is large" dialog: Prism Terminal has none.
   Bracketed paste is the multi-line safety (a shell that did not ask for it receives the lines, as
   in xterm). Adding a confirmation would be a new feature; it is a Question if the owner wants it.
   This leaves the roadmap Review Focus line "hostile text (... multi-line) ... inert until the
   user acts" met for bracketed shells only (cmd never asks for bracketed paste); Question 4 says so.
D16. **Selected-cell fill is the theme's selection colour blended over the ground and painted as a
   solid colour** (never alpha), because both painters write rectangle colours without blending;
   text keeps its own colour. Compared by eye with Prism Terminal in the Task 27 side-by-side.
D17. **Find bar belongs to one tab** (PT `findFor`): switching tabs closes it for the old tab and
   shows nothing for the new one; the bar closing clears highlights; closing leaves the selection.

D18. **OSC 8 links come from alacritty's per-cell hyperlinks** (`Cell::hyperlink()`), which alacritty
   fills from the stream itself, not from M2's stream-tracked `Osc8Spans`. A cell carries its link
   through scroll, trim, reflow and the alternate screen and loses it when overwritten, which is what
   the parity lines ask. M2's `osc8.rs` stays as ported library code (its 25 tests stand); M5 uses its
   `is_web_link` and `osc8_target`. Verified: `Cell::hyperlink(&self) -> Option<Hyperlink>` with
   `id()` and `uri()` is public in 0.26.0, and Flare's scanner forwards every byte to the processor.

/// Where a pointer is on the grid image. `x` and `y` are PHYSICAL pixels from the image's top-left.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Hit {
    pub col: usize,   // clamped to 0..cols-1
    pub row: i64,     // NOT clamped: -1 or less above the first row, `rows` or more below the last
    pub right: bool,  // the pointer is in the right half of its cell (left half of a clamped column: false)

/// How far (device pixels) the pointer is beyond the cell area vertically: 0.0 inside, negative above
/// the top of row 0 (`y - pad`), positive below the bottom of the last row (`y - (pad + rows*cell_h)`).
pub fn past_edge_px(y: f64, m: &CellMetrics, rows: usize) -> f64;

/// A CSS/logical length to device pixels at `scale` (no rounding): `v * scale`.
pub fn to_phys(v: f64, scale: f32) -> f64;

## Task 3: The alacritty buffer as a BufferLike (Sonnet)

**Files:** `crates/flare-term/src/term_buf.rs`. Source: M2 `cells.rs` traits; alacritty 0.26 `Term`/`Grid`
(`grid()[Line(i)]`, `history_size()`, `screen_lines()`, `columns()`, `Flags`). Existing consumers
take `&dyn BufferLike` with ABSOLUTE rows `0..len()`: row 0 is the oldest history line.

```rust
use alacritty_terminal::event::EventListener;
use alacritty_terminal::term::Term;
use crate::cells::{BufferLike, LineLike, ScratchCell};

/// Absolute row <-> alacritty line. `hist` is `term.history_size()` at the moment of the call.
pub fn abs_to_line(hist: usize, abs: usize) -> alacritty_terminal::index::Line; // Line(abs as i32 - hist as i32)
pub fn line_to_abs(hist: usize, line: alacritty_terminal::index::Line) -> usize;  // (line.0 + hist as i32).max(0)
/// The absolute row shown on viewport row 0: `history_size - display_offset`.
pub fn viewport_top<T: EventListener>(term: &Term<T>) -> usize;
/// `history_size + screen_lines`.
pub fn total_rows<T: EventListener>(term: &Term<T>) -> usize;

/// A read-only window onto the term's rows `[first, last]` (absolute, clamped), extended upward
/// while its first row continues the row above, and downward while the next row continues this
/// one, at most 200 rows each way. `len()` is `total_rows`; `line(y)` is `None` outside the window.
pub struct TermBuf<'a> { /* rows: Vec<RowRef<'a>>, first: usize, total: usize */ }
impl<'a> TermBuf<'a> {
    pub fn window<T: EventListener>(term: &'a Term<T>, first: usize, last: usize) -> Self;
    /// The whole buffer (history plus screen). Allocates one small struct per row: for a click or a
    /// search step, never per frame.
    pub fn all<T: EventListener>(term: &'a Term<T>) -> Self;
}
impl BufferLike for TermBuf<'_> { /* len, line */ }
```
`RowRef::is_wrapped()` is true when the row ABOVE ends in a cell with `Flags::WRAPLINE` (the xterm
meaning: this row continues the previous one). `load_cell(x, into)`: `into.width` = 2 for
`WIDE_CHAR`, 0 for `WIDE_CHAR_SPACER`, else 1 (a `LEADING_WIDE_CHAR_SPACER` is an empty width-1

**The rules (each is a test below).** `mouse_owned = mode.mouse != None && !shift`. Pointer positions arrive in
CSS px relative to the grid area (Task 19); every hit test uses `hit_cell(x_css * scale, y_css * scale, ..)`
(device px from the grid image's top-left) and every row a `Hit` gives is clamped to `0..rows` before use. Scroll
amounts from `sel_machine` and `find` are positive toward NEWER output; `TermHandle::scroll_view` takes positive
toward OLDER, so they are always applied as `scroll_view(-n)`. Never hold the `DecorInputs` borrow across a call
into the handle's waker, Slint or a closure from `TermDeps`.
1. *Left press.* `mouse_owned`: send the press report (`encode_mouse`, `write_report`), start the program-copy
   watch (`down`), no selection. Otherwise: click count from `ClickCounter::new(dbl.time_ms, dbl.dx, dbl.dy)` in
   device pixels; `hit_cell` then `SelMachine::press` (alt = block) and `sel_apply`; remember the press cell, point
   and the link mark under it. `focus_terminal` is true for every press; any press puts the menu away.
2. *Move with the left button held.* Reporting: a Drag/Any report when the cell changed. Selecting:
   `Drag { row, col, right, past_css_px: past_edge_px / scale }`, `sel_apply`; the auto-scroll timer (every
   `DRAG_SCROLL_MS`, from `tick`) calls `scroll_view(-lines)` then `after_scroll`.
3. *Move without a button.* The hovered mark sets the cursor to `Pointer` and `DecorInputs.hover`; otherwise
   `Text`, or `Default` while `mouse_owned`; Any tracking reports buttonless motion on a cell change.
4. *Left release.* Reporting: the release report; the watch's `up`. Selecting: `release`; an empty selection is
   cleared; then `dragged = hypot(release - press in device px) > cell_w / 2 || has_selection()` (PT
   `attachClickCaret`). When NOT dragged: if the press and the release are on the same link mark ->
   `click_action(&mark.target, shown_for(&mark), base, 0)` where `base` is, for a `Path` mark,
   `paths.find_path(owner, cwd, text, now)`'s `Found::Hit(PathFound { base, .. })` (anything else: nothing
   opens) and None for the other kinds; `OpenUrl(u)` -> `open_url(&u)` only when `is_web_url(&u)`;

5. *Right.* The press is reported only when `mouse_owned` and no selection stands. The release opens the menu at the

6. *Middle* is reported when `mouse_owned`, otherwise ignored.

# Appendix C: rules and features to write in Task 28

**New regression rules (text for `docs/regression-rules.md`; the numbers 142 to 147 assume M3 and M4 added none, so Task 28 renumbers from the highest existing rule):**
142. **Selection, find and links work on cell boundaries and logical lines, never on strings.** A selection end is a boundary in `0..=cols` of an absolute row; a wide character is taken whole; text comes from `cell_text` and `selection_text`, and a search maps characters back to cells through the line's index. Native: `sel_machine.rs`, `sel_text.rs`, `find.rs`, tests `a_wide_character_is_taken_whole`, `wide_characters_count_two_cells`. Source: rule 21; xterm `SelectionService`.
143. **A drop is typed, not pasted, and is inert.** Dropped paths go through `quote_paths` for the shell that RUNS in the tab (`TermHandle::shell_id`, never the requested id; nothing is typed before the shell started) and `send_text`; a refused path types nothing; no Enter, no trailing space; only over a live shell. Native: `drop_flow.rs`, tests `a_control_character_in_a_name_types_nothing`, `several_files_are_joined_by_one_space_and_never_end_in_enter`. Source: regression-rules file-drop-and-menu (#16); rule 135.
144. **Mouse reports are bytes, not typing, and Shift gives the selection back.** A program that asked for the mouse gets press, release, motion and wheel; a right click still opens the menu; no report marks the tab typed. Native: `mouse_report.rs`, `TermHandle::write_report`, tests `a_program_that_owns_the_mouse_gets_press_release_and_motion`, `write_report_is_not_typing`. Source: xterm `MouseStateService`; rule 9.
145. **A link click opens http(s) or an allowlisted path and a right click opens nothing; every path is opened through `open_term_path(base, text, ..)`, never by an absolute path from the UI; scans cover the viewport and no pass holds the UI.** Native: `link_target.rs`, `link_scan.rs`, `scan_plan.rs`, tests `any_other_button_opens_nothing`, `a_burst_of_scrollback_is_not_scanned`, `the_count_job_walks_in_slices_and_counts_in_reading_order`. Source: rules 14, 15, 16, 134; two-apps #95.
146. **The clipboard is read and written off the UI thread; a copy is refused, never trimmed; the program is told nothing.** Native: `ClipboardPort`, `copy_async`, `read_async`, `BoundedClip` (8 ms), tests `copy_async_refuses_empty_and_oversize_without_touching_the_clipboard`, `no_blocking_clipboard_call_on_the_ui_thread`. Source: `ipc.ts writeCapped`; rules 10, 34.
147. **Decorations are opaque solid colours in whole device pixels.** The selection is the theme colour blended over the ground in Rust; outlines and underlines are `max(1, floor(scale))` pixels; no alpha reaches a rectangle on either painter. Native: `decor.rs`, tests `the_selection_is_the_opaque_blend_over_the_ground`, `a_find_outline_is_hair_thick_and_outside_the_box`, `gpu_and_cpu_agree_with_a_decor`. Source: rules 23, 131; M3 Verified facts (hairline).

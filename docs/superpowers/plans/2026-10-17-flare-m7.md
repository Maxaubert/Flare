> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (run as a
> Workflow, one `agent()` per task, waves in parallel). Steps use checkbox (`- [ ]`) syntax. Every
> task is TDD: write the failing test, run it and see it fail, implement, run it and see it pass,
> commit. Each task names its model: **Haiku** unless marked **Sonnet**. Opus only reviews (Task 53

> orchestrator names in your task prompt (one folder per builder, never `target` and never another
> builder's folder). That includes `cargo build`, `cargo nextest run`, `cargo clippy`, `cargo fmt

> **Staging rule (parallel builders share ONE worktree):** stage only the files your task lists
> (`git add <exact paths>`, never `git add -A` or `git add .`, never `git commit -a`), commit only
> those, and never touch another task's files. **Only Task 1 and the orchestrator edit any
> `Cargo.toml`, any `lib.rs` or `mod.rs`, `main.rs` module lists, `build.rs`, `ui/settings/types.slint`

> between waves. `cargo nextest run -p <crate> <filter> --target-dir <TARGET>` while iterating, the
> whole workspace only in Task 54.

> crate, and `crates/flare/build.rs` compiles every Slint file) is not yours to fix: wait two minutes and
> build again; after three tries report it to the orchestrator. Never edit, stash or revert another
> task's file. A Slint task compiles its own file at once (`cargo build -p flare --target-dir <TARGET>`) and
> commits only when that passes.
> **Same-file pairs run one after the other, never together:** Tasks 41, 42, 43 and 44 (they all edit
> `settings_ctl.rs`, `appctl.rs`, `window.rs` or `app.slint` wiring) run in that order. Tasks 20 to 23 each

## Global Constraints

Copied from the roadmap and M2 to M6; every task obeys them.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes** anywhere (code comments, docs, test
  strings, UI copy, the JSON fixtures, the Node scripts); CI greps for them. The catalogue JSON is generated
  from Prism Terminal's files, which a test proves have none.
- Flare's own names only: setting keys `flare.*` (decision O10), profile `%APPDATA%\Flare`, e2e seams
  `FLARE_E2E_*`. Never a Prism name in an identifier, path, key, header or string of Flare's own. **The one
  allowed place for the string `prism.` and the folder names `PrismTerminalStable` / `PrismTerminal` is the folder
  `flare-settings/src/import/`**: `map.rs` (the left column of the import table), `legacy.rs` (the two legacy keys),
  `run.rs` (the two profile folder names in `candidates`) and the `#[cfg(test)]` fixtures of `ldb.rs` and `run.rs`
  (Local Storage fixtures hold `prism.*` keys), plus `crates/flare-settings/tests/import_e2e.rs` (Task 50); the scan
  test of Task 44 fails on any other `prism.` literal in `crates/*/src`. Docs and comments may name Prism Terminal as the source.
- **Every display scaling works** (roadmap, owner 2026-10-17: "it has to work on all sorts of different DPI
  scalings, like 150 or 200 percent"): 100, 125, 150, 175, 200, 225, 250 and 300 percent, both renderers,
  moving the window between monitors of different scalings. For this milestone: the whole Settings page is
  laid out by `flare_settings::layout` in logical pixels whose EDGES are snapped to whole device pixels (every
  row, panel, tile, hairline and control box starts and ends on a device pixel, and two neighbours share their
  edge exactly: no gap, no overlap, at all eight scales); hairlines are `Px.hair()`; text sizes are logical
  pixels (Slint scales them); the UI tests of Tasks 45 to 49 run at the eight scales; the screenshots are every
  page at 100, 150 and 225 beside Prism Terminal and two pages at all eight (Task 52).
- **Look = Prism Terminal's, measured, not remembered.** Every size in this plan comes from the Tailwind classes
  in `PT/` and from Task 3's measured `pt_settings_metrics.json`; a layout test compares Flare's numbers to
  that file within 1 CSS px (a documented difference only where Slint's text metrics differ from Chromium's).
- **Settings write stores and nothing else** (PT AppearancePage header): the window, the grid and the chrome
  follow `LookStore`'s change listener (M4's `LookCtl`); no settings code repaints anything by hand.
- **Settings ask nothing nobody changed** (rule 77): a colour or code field commits only on Enter or on losing
  focus, only with parseable text that differs from the stored colour in any form (`colour_commit`); focus
  traversal, Escape and opening and closing a picker with no change store nothing and never pin a following row.
- **Controls are neutral; only Save changes and an ON switch wear the accent** (rule 78, PT `neutralControls.test`):
  the chosen rail page is a grey fill (`hover-hi`), never the accent; focus on a row is a fill, on a bordered
  control a lighter edge, never a ring; the only accent outside those two is the flash (a mark, not a button) and
  the keyboard focus ring of the colour field and the help panel's own controls, as PT.
- **Settings copy is plain words** (rule 79): every label and subtext is letters, digits, spaces, commas and full
  stops only, a subtext is at most eight words, a subtext names no key; see decision D5 for the two rows that break
  a rule on purpose (O8).
- **Escape is handled once** (rule 83): the find field with text clears; an open colour popover reverts; otherwise
  the host's. **Command help never inserts, runs or types** (rule 82): the panel's only effect is a `Fn(String)` copy
  callback; a test counts pty writes across search, copy and Enter and requires zero.
- **Never write into Prism Terminal's folders** (design spec Migration): the importer reads a COPY made in a
  temp folder of Flare's own; a test hashes every file of the source before and after.
- **Persistence is atomic and never reads/writes `%APPDATA%\Flare` in tests** (rules 36, 40): tests use
  `PrefStore::memory()` or a `tempfile` folder; unknown words read the default and are never written back.
- **UI thread never waits (rule 34):** the Local Storage copy and read, the shell list, the registry (M9) and the
  catalogue's first index build run on worker threads; any blocking call in non-test code of `flare-settings`,
  `flare-help`, `flare-diag`, `flare-win` or `flare` carries `// sync-ok: <reason>` on the same line (M2's scan
  tests enforce it; Task 54 extends them to `flare-help`).
- New dependency = a reason line in `README.md`'s dependency list and a `THIRD-PARTY-NOTICES.md` entry in the same
  PR (Task 54); `cargo deny check` passes. Pin with `=`. Every `pub fn new() -> Self` with no arguments also gets
  `impl Default`.
- CI gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo nextest run --workspace`, `cargo deny check`.
- Nothing in tests may open a visible window, take the foreground, touch the real clipboard, the real
  `%APPDATA%\Flare`, the real registry or the owner's Prism Terminal folders. The ONE exception is a test marked
  `#[ignore]` that reads a COPY of a real Prism Terminal Local Storage folder named by `FLARE_REAL_PT_LEVELDB` (Task 13),
  run by hand. Tests that need a folder use `tempfile`; UI tests use the headless software platform only.
- Builders: Haiku by default, Sonnet where marked. Reviews: Opus. Never Fable.
- The PR reports test counts, the screenshots (Task 52), the metrics comparison (Task 45), the import timing
  on this PC's real Stable profile (Task 50) and the Opus findings.

## Review Focus

- **Never write into Prism Terminal** (Tasks 13, 26, 50): the importer opens only its own temp copy; the source folder
  is read with `std::fs::copy` of each file except `LOCK`; no `create_dir`, `remove`, `set_permissions` or `OpenOptions`
  write on a path under the source; the hash test and a grep test hold it. Opus reads `import/` end to end.
- **Skip, never guess** (Tasks 14, 15, 26): an unreadable value, a value of an unknown shape, a torn copy, a missing
  profile and a non-UTF-16 value import nothing for that key; a value is validated by the same reader the app uses;
  the report lists skipped keys by name with the reason.
- **One writer per key** (Tasks 12, 19, 25): every setting key is written through the module that owns it (M3, M4, M6's
  getters and setters, and this milestone's `help_prefs`, `colour_format`); `actions.rs` calls them and defines no second
  setter; the key scan test of Task 10 holds the row tables to the keys the modules store under. The ONE other writer is
  the once-only importer (Task 26), and it writes only the canonical text that the owning module's own reader returned for
  the candidate value (Task 14), so it can never store a value the owner would not have written.
- **Search reaches every row it indexes** (Tasks 11, 18, 47): the index is built from the same tables the pages draw; a
  test types every label, chooses the first result and checks the page, the row id and the flash; a row that is not drawn
  on this PC (the GPU row without NVIDIA, the dictation rows before M8) is not indexed.
- **Help search equals Prism Terminal's** (Tasks 2, 6, 27): thousands of golden vectors made by Prism Terminal's own
  `searchHelp`; ids and scores equal; the catalogue is data generated from PT, never typed.
- **The picker is the most stateful widget** (Tasks 16, 36, 42, 48): Escape reverts exactly the opening value (an unset
  state included), a press outside keeps the colour, a left-open picker returns after a tab switch, writes are one per
  frame, the eyedropper never reaches a test machine's screen (the seam answers).
- **Display scaling** (Tasks 24, 45, 52): look at the eight-scale screenshots of Appearance and Terminal row by row:
  hairlines one device pixel from the icon column, tiles square, the wall cards the same height, the select popup edge,
  the slider thumb centred on its track, the switch knob inside its track.
- **Contrast and neutrality** (Task 46): label and subtext 4.5:1, icon 3:1, warning 4.5:1 on a dark and a light theme;
  rendered pixels prove only Save and an ON switch use the accent.

## Decisions taken by the planner (not the owner)

D1. **A new crate `flare-help`** holds the command help (types, search, the catalogue). `docs/test-port.md` maps
   `core/shared/help/*.test.ts` to `flare-settings`; the catalogue is about 1.2 MB of data and its tests are heavy, so it
   gets its own crate (as M3 gave the tab logic `flare-tabs`). Task 54 updates the ledger rows.
D2. **The catalogue is data, generated, never typed.** Task 2's Node oracle loads Prism Terminal's seven catalogue files
   (`powershell.ts` and the others), dumps them to `crates/flare-help/data/<name>.json`, and runs `searchHelp` over
   thousands of queries into `crates/flare-help/tests/fixtures/golden_search.json`. The Rust search is checked
   against the golden file for ids and scores; a builder never retypes a command.
D3. **`flare-settings` owns the Settings logic UI-free:** the page models, the layout arithmetic, the actions. Slint draws
   rectangles at positions Rust computed (M3's decision D5 for the strip, extended): a page is a list of sections, each a
   panel of blocks, every block with a snapped `y` and `h`; Slint never lays a row out by itself. This makes "layout is
   measured" (rule 81) a pure-Rust assertion and makes scroll-to-row and the flash exact.
D4. **The row tables use Flare keys** (`flare.term.shell`, and so on, O10). The import table (Task 14) is the only place
   that knows the `prism.*` names. The `explorer-verb` row stores nothing (`registry`), as PT.
D5. **Copy rules and the two exceptions.** The See-through row keeps Prism Terminal's nine-word subtext "How much of the
   desktop shows behind every surface." (O8: parity beats the copy rule), so the eight-word test names that one row as

```
**Port rules (JavaScript semantics that Rust does not give for free; each has a test):**
1. **UTF-16 lengths.** `word.length`, `.slice(0, 40)` and `charCodeAt` count UTF-16 code units. Use a helper `u16len(&str)` and `truncate_u16(&str, n)` (cut at a char boundary at or below n units); `within_one_edit` works on `Vec<u16>` from `encode_utf16`.
2. **tokenise:** NFKD (`UnicodeNormalization::nfkd()`), drop every char for which `unicode_normalization::char::is_combining_mark` is true, remove `'`, U+2019, U+02BC and the backtick, lower-case (`to_lowercase`), split on every char that is not `is_alphabetic() || is_numeric()`, drop empty parts, cut each part to 40 UTF-16 units.
3. **JS whitespace:** `flat_command` collapses runs of the JS `\s` set (TAB LF VT FF CR SPACE, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF) to one space and trims the same set: write `is_js_space(char)`, never use `split_whitespace`.
4. **Insertion order is semantics.** The JS `Map` iterates in insertion order and two places depend on it: the vocabulary (`postings.keys()` order decides which of two words claims a shared synonym key in `candidates`, because `if (!out.has(k))` keeps the first) and the per-entry `fields` map (decides the order words enter `postings`). Use `Vec<String>` for the vocabulary pushed on first sight and a `Vec<(String, Vec<f64>)>` plus a `HashMap<String, usize>` per entry for `fields`. Never iterate a bare `HashMap` where the TS iterates a `Map`.
5. **`Math.round`** is `floor(x + 0.5)`: `fn js_round(x: f64) -> f64`. The final score is `js_round(total * 100.0) / 100.0`. All arithmetic is `f64` in the TS operation order (`sum[i] += best[i]` word by word, `worth += ALSO * held[j]` after sorting `held` descending).
6. **`Float64Array`/`Uint8Array`** become `Vec<f64>`/`Vec<u8>` of `entries.len()`; `best.fill(0)` runs per word.
7. **Sort:** `score` descending (`b.score - a.score`), then the UTF-16 length of the task ascending, then the id by plain `<`/`>` string comparison (ids are ASCII), a stable sort (`sort_by`).
8. **Stage split** for `stages`: split the lower-cased flat command on the alternatives `||`, `&&`, `|`, `;` (scan left to right, longest of `||`/`&&` first), drop the first part, trim each, strip one leading `sudo `, take the text up to the first space, drop empties.
9. **Robustness** (`search.test.ts` "whatever it is handed"): Rust types forbid most bad input; keep `search_help` total: an empty slice, an empty or blank query, a query over 400 UTF-16 units (cut), a limit of 0 (no limit), and entries with empty fields never panic.
10. **The index** is built once per entries slice: `fn index_for(entries) -> &'static Index` through a `OnceLock<Mutex<Vec<(usize ptr, usize len, Arc<Index>)>>>` keyed by the slice's pointer and length (the TS keys a WeakMap by array identity and rebuilds when `count` differs); `all_help()` is `'static` so the real catalogue is indexed once. A test builds an index over a throwaway `Vec` and over `all_help()` and checks the second search does not rebuild (a build counter behind `#[cfg(test)]`).

```
The reader runs on a `std::thread::spawn`ed worker that owns clones of the paths and the `Arc`; the result comes back over an `mpsc` channel with
`recv_timeout(ceiling)`. On a timeout the worker is left to finish on its own (its drop guard still removes its temp folder) and its late answer is ignored.
**Algorithm.** `AlreadyDone` when `DONE_KEY` is set. For each candidate in order, run `ldb::read_local_storage` on a worker thread and wait `recv_timeout(ceiling)` (1.5 s in the app); classify: `Keys` (at least one value whose name starts `prism.`) wins and stops the search; `Empty` or `NoFolder` continues to the next candidate; an I/O failure, an open failure or a timeout stops the search at once
and does NOT fall through to the next candidate (the Stable profile is the owner's; an old Main profile must not stand in for it). With a winner: build the source map, `legacy::migrate`, `map_one` each pair; write every `Write` whose Flare key is not already set (a key Flare already holds is `already_set`, Flare's own choice wins), `Skip`s go into `skipped` with the reason,
`Retired`/`Unknown` are counted; flush the store; write `DONE_KEY` = JSON `{"v":1,"status":"imported","origin":"stable","written":N,"skipped":[["prism.x","reason"]],"at":<unix seconds>}` and flush. Nothing found -> done with `"status":"nothing"`. I/O failure -> `ATTEMPTS_KEY` + 1 and `Status::Retry` (no `DONE_KEY`); when the attempts were already 3 -> done with `"status":"gave-up"`.
The log line (`log::info!`) names counts and keys only, never values. The temp folder is gone afterwards.

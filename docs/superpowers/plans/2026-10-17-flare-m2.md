**Goal:** A live tab in the M1 window. Flare starts the saved/default shell (PowerShell 7, else
Windows PowerShell, with cmd and WSL detected too) in a ConPTY served by the BUNDLED `conpty.dll`
and `OpenConsole.exe`, feeds its output through `alacritty_terminal` into the M1 `Grid` for both
renderers, takes keyboard input from physical keys, resizes without losing the prompt line,
scrolls its 10,000-line scrollback with the mouse wheel, batches output every 8 ms, survives a
runaway `cat`, and on quit kills every shell and waits (3 s cap) until each is gone. Every Prism
Terminal v0.55.6 unit test that `docs/test-port.md` maps to `flare-term` and `flare-shells` is
ported as a Rust test (ledger in Appendix A).

**Architecture:** Two UI-free crates plus app wiring.
`flare-shells`: shell list and detection, command lines, environment, prompt hooks, cwd reports,
paste and path quoting (pure functions, no window, no pty).
`flare-term`: `Emulator` (an `alacritty_terminal::Term` + the `vte` processor + a small byte
`Scanner` for the OSC and CSI queries alacritty does not surface + the ConPTY-faithful resize),
`PortablePty` (portable-pty over the bundled ConPTY), `SessionManager` (spawn, pending, warm shells,
kill, quit-wait; all against traits so fakes test it), `TermHandle` (one tab: emulator + session +
input encoding + wake), and the pure PT rules (cells, links, paths, OSC 8/52, replies, click-caret,
selection edit, caret hold, app-copy notice, path links, path open).
`flare` (M1 crate): `GridHost` gets a `GridSource` seam so the live terminal replaces the sample
grid; a winit event filter turns physical key events into `flare_term::keys::KeyEvent`.

## Global Constraints

Copied from the roadmap; every task obeys them.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes** anywhere (code comments,
  docs, test strings, UI copy); CI greps for them.
- Flare's own names only, never Prism names in identifiers, env vars, paths, OSC payloads:
  `FLARE_TAB_ID`, `FLARE_RESUME_ID`, global PowerShell variable `__flarePrompt`, XTVERSION
  `Flare <version>`. Test strings may contain Prism-looking *paths* only as inert data.
- New dependency = a reason line in `README.md`'s dependency list and a `THIRD-PARTY-NOTICES.md`
  entry in the same PR; `cargo deny check` passes (Task 29). Pin with `=`.
- CI gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo nextest run --workspace`, `cargo deny check`. Every `pub fn new() -> Self` with no
  arguments also gets `impl Default`.
- Nothing in tests may open a visible window or take the foreground. ConPTY sessions are
  windowless; that is allowed. A test that starts a real shell reaps it (kills and waits) on every
  path, including failure (use the `Guard` in `tests/common`, Task 23).
- **UI thread never waits (rule 34).** Probes, stats, spawns, reads of the clipboard run on worker
  threads; any blocking call in `flare-term/src` or `flare-shells/src` outside `tests` carries a
  `// sync-ok: <reason>` comment on the same line, enforced by a scan test (Task 24).
- **Replies only when asked (rule 10).** Every byte Flare writes back to a pty answers a query in
  that pty's own stream. OSC 52 reads are never answered. No unsolicited bytes.
- **Typing is heard from keys (rule 9).** `TermHandle::last_typed()` moves only on key and text
  input, never on replies, cd lines or pastes made by Flare itself.
- **Cells are not characters (rule 21).** All screen maths is in grid columns using `WIDE` and
  `WIDE_SPACER`; text positions come from `cells::cell_text`, never `len()` of a screen string.
  Text positions in this crate are **char indices** (Unicode scalar values), not bytes.
- Builders: Haiku by default, Sonnet where marked. Reviews: Opus. Never Fable.
- The PR reports the throughput numbers of Task 24 and the resize evidence of Task 20.

## Review Focus

- **The O3 resize finding is the heart of this milestone.** Plain `Term::resize` under ConPTY
  corrupts the prompt (stray duplicate of the typed text, the banner pushed into history, the
  typed text landing on the wrong row). `resize_conpty` (Task 20) fixes it with a vertical
  re-anchor, not a cursor-line carry. Opus re-runs the real-ConPTY tests (Task 24) and reads the
  RED output recorded in Task 20 before accepting.
- **Quit and kill (rules 28, 29, 30).** No path may leave a shell running, hang the UI, or abort
  the process. The `ten_real_shells_killed_none_remain` and `kill_while_output_flows_50_times`
  tests pin it. Check that every thread is joined or provably finishes after the quit-wait.
- **Replies and typing.** Read `Emulator::feed` for any byte written back that no query asked for;
  read `TermHandle::send_key` for anything that could mark replies as typed.
- **Throughput.** A 100 MB flood keeps `snapshot()` under 100 ms at its worst and Ctrl+C
  (0x03) stops an infinite writer within 5 s (Task 24). Backpressure (reader blocks at 4 MiB
  backlog) must not deadlock with a resize.
- **Bundled ConPTY.** The OpenConsole.exe serving a Flare pty must be the bundled one (module
  path check plus a process image path check); a missing or altered file fails loudly at startup.
- **Wide-character width tables** differ: alacritty uses `unicode-width 0.2` (Unicode 16), Prism
  Terminal's xterm used the Unicode 11 table. Newer emoji are 2 cells here and 1 there. Not a
  bug (modern programs measure with modern tables); M10's wide-character e2e decides.

## Verified facts (2026-10-17; prototype in `scratchpad\proto-m2`, all run on this PC)

**portable-pty 0.9.0 can load a specific conpty.dll only by side-loading.** Its
`src/win/psuedocon.rs` does `ConPtyFuncs::open(Path::new("conpty.dll"))` (a bare name, so the normal
DLL search order: application folder first) and silently falls back to kernel32's inbox ConPTY if
that fails. There is no API for a path, and it hardcodes
`CreatePseudoConsole` flags `INHERIT_CURSOR | RESIZE_QUIRK | WIN32_INPUT_MODE` (= 7).
**The smallest correct way is to PRELOAD the DLL by absolute path before the first `openpty`:**
`LoadLibraryExW(<dir>\conpty.dll, null, LOAD_WITH_ALTERED_SEARCH_PATH)`. Windows then resolves the
later bare-name `LoadLibraryW("conpty.dll")` to the module that is already loaded. Proven: after the
preload, `GetModuleHandleW("conpty.dll")` + `GetModuleFileNameW` returned the bundled path, and the
process list showed `OpenConsole.exe` running **from the bundled folder** (conpty.dll starts the
OpenConsole.exe next to itself). The exe and the DLLs need not share a folder with each other.
**Flags do not matter here:** the same scenarios were run through portable-pty (flags 7) and
through an own `CreatePseudoConsole` wrapper with flags 0, 1, 2, 4 and 7; byte counts and screens
were identical. So no own wrapper is needed and portable-pty stays. (An own wrapper would be ~150
lines of windows-sys; the prototype `scratchpad\proto-m2\src\own.rs` is the fallback if portable-pty
ever misbehaves.) portable-pty also pulls `winapi 0.3`, `shared_library`, `winreg`, `nix`,
`serial2`; `cargo deny` must accept their licences (all MIT or Apache-2.0 or BSD).
`CommandBuilder::new` starts from the process environment AND merges the registry environment, so
**always call `env_clear()` and then set every variable** (PT passes its env exactly as given).
A cwd that is not a directory is silently replaced by `%USERPROFILE%`; Flare checks the folder first.

**ConPTY's startup talks to the terminal and waits.** The first bytes from OpenConsole were
`ESC[1t ESC[6n ESC[c ESC[?1004h ESC[?9001h ESC[1;1H ...`: a CPR query (`ESC[6n`), a DA1 query
(`ESC[c`), focus-reporting and win32-input-mode requests. alacritty's `Term` answers CPR
(`ESC[1;1R`) and DA1 (`ESC[?6c`) through `Event::PtyWrite`; **those events MUST be written back to the
pty** or ConPTY can stall. PSReadLine also sends `ESC[6n` while typing. Prism Terminal (xterm.js)
answers DA1 as `ESC[?1;2c`; Flare rewrites alacritty's `ESC[?6c` to `ESC[?1;2c` (parity with the
e2e termReplies check). Focus (`?1004`) and win32-input (`?9001`) requests are ignored; Flare
sends plain VT keys, which ConPTY accepts.

**alacritty_terminal 0.26.0 API (compiled and used):**
`Term::new(Config, &impl Dimensions, impl EventListener) -> Term<T>`;
`Dimensions { fn total_lines(&self)->usize; fn screen_lines(&self)->usize; fn columns(&self)->usize }`;
`alacritty_terminal::vte::ansi::Processor` (`Processor::new()`, `proc.advance(&mut term, &[u8])`);
`Term::resize(impl Dimensions)`; `term.grid()` / `grid_mut()` -> `Grid<Cell>`; indexing
`grid[Point::new(Line(i32), Column(usize))]` with `Line` negative for history;
`grid.history_size()`, `grid.display_offset()`, `grid.screen_lines()`, `grid.columns()`,
`grid.cursor.point`; `term.scroll_display(Scroll::Delta(i32))` (positive = toward older output),
`Scroll::{Top,Bottom,PageUp,PageDown}`; `term.mode() -> &TermMode` with flags `SHOW_CURSOR`,
`APP_CURSOR`, `BRACKETED_PASTE`, `ALT_SCREEN`, `MOUSE_REPORT_CLICK`(1000), `MOUSE_DRAG`(1002),
`MOUSE_MOTION`(1003), `SGR_MOUSE`, `ALTERNATE_SCROLL`, `FOCUS_IN_OUT`;
`alacritty_terminal::sync::FairMutex<T>` (`lock()` fair, `lock_unfair()`, `lease()`);
`Cell { c: char, fg, bg, flags: Flags, extra }` with `cell.zerowidth() -> Option<&[char]>`,
`cell.hyperlink()`; `Flags::{INVERSE,BOLD,ITALIC,UNDERLINE,WRAPLINE,WIDE_CHAR,WIDE_CHAR_SPACER,DIM,
HIDDEN,STRIKEOUT,LEADING_WIDE_CHAR_SPACER,DOUBLE_UNDERLINE,UNDERCURL,DOTTED_UNDERLINE,
DASHED_UNDERLINE,ALL_UNDERLINES}`; `vte::ansi::Color::{Named(NamedColor), Spec(Rgb{r,g,b}),
Indexed(u8)}`, `NamedColor` numbers: `Black..White = 0..=7`, `BrightBlack..BrightWhite = 8..=15`,
`Foreground = 256`, `Background = 257`, `Cursor = 258`, `DimBlack..DimWhite = 259..=266`,
`BrightForeground = 267`, `DimForeground = 268`; `Event::{Title(String), ResetTitle, Bell,
PtyWrite(String), ColorRequest(usize, fmt), ClipboardStore, ClipboardLoad, TextAreaSizeRequest,
Wakeup, CursorBlinkingChange, MouseCursorDirty, Exit, ChildExit(ExitStatus)}`;
`Config { scrolling_history: usize (default 10000), osc52: Osc52, kitty_keyboard: bool, .. }`;
`Grid::scroll_up::<vte::ansi::Color>(&Range<Line>, usize)` is public and moves the top rows into
history (used by the resize fix). alacritty has **no** surface for OSC 9;9, OSC 777, XTVERSION
(`CSI > q`) or arbitrary OSC: they are dropped inside `vte`. Hence the byte `Scanner` (Task 14).
`Osc52::Disabled` stops alacritty's own clipboard events; Flare parses OSC 52 itself (PT's rules).
**Synchronized updates (DEC mode 2026) need a timer from the host** (read in `vte-0.15.0/src/ansi.rs`,
review 2026-10-17): after `ESC[?2026h` the `Processor` BUFFERS every later byte (up to 2 MiB) until
`ESC[?2026l`; its 150 ms timeout is only a deadline it stores (`proc.sync_timeout().sync_timeout() ->
Option<Instant>`, `StdSyncHandler`), and nothing releases the buffer when it passes: alacritty's own event
loop calls `proc.stop_sync(&mut term)` once the deadline is over. Without that call a program that opens a
synchronized update and never closes it (killed mid-frame, a bug, a dropped byte) freezes the tab's
screen while its output keeps arriving. Claude Code paints with mode 2026. Hence
`Emulator::sync_deadline` / `release_sync_if_due` (Task 18) and the handle's sync timer (Task 22).
Also verified in source: `TermMode::default()` includes `ALTERNATE_SCROLL` (so the alt-screen wheel sends
arrows from the start); setting mode 1002 or 1003 removes the other mouse modes (`MOUSE_MODE` bits), so at
most one of `MOUSE_REPORT_CLICK`, `MOUSE_DRAG`, `MOUSE_MOTION` is set.

**O3 outcome (decision O3, measured with real cmd.exe, PowerShell 7 and the bundled ConPTY):**
ConPTY keeps its viewport **top-anchored** and reflows only the visible screen rows; alacritty
keeps the cursor row fixed (**bottom-anchored**) and pushes extra rows into history, pulls history
down on widening. ConPTY then sends absolute cursor addressing for the cursor line, so the two
models disagree. Plain `Term::resize` result (cmd, 73-char prompt, `abcdef` typed, 80 -> 60 -> 40 -> 100 -> 80):
the banner lines go into history, ConPTY's rewrite `ESC[8;14H ESC[J abcdef` lands on a row of
its own and leaves a **stray duplicate `abcdef` row**; widening a full screen erases the prompt
(`ESC[J` from the wrong row). ConPTY sends 0 bytes on a resize when only the prompt is on the line
(and for PowerShell, which redraws itself), but ~30 bytes of cursor-line repaint when text is
typed after a cmd prompt. The PT-style *cursor-line carry* (rewrite the line) is **not needed**.
What fixes every scenario tried (columns 60/40/100/80, rows 30/18/24/10, a screen full of output,
pwsh) is to compute where ConPTY will have the cursor row and shift alacritty's grid vertically to
match (Task 20, the algorithm is given there and was run on this PC): reflow only the old screen
rows to get `row_target`, call `Term::resize`, read `row_actual`, then pull history down
(`row_target > row_actual`, by growing then shrinking the line count) or push rows into history
(`row_target < row_actual`, `Grid::scroll_up`). Skipped when the alternate screen is active or
non-blank rows sit below the cursor line (the same "tail" test PT used).

**ConPTY throughput on this PC (RTX 5090 box, release):** a native writer (`spew`, 64 MB of
111-byte lines, 40x120 pty) arrives at **15.9 MB/s** end to end through the bundled ConPTY; the
alacritty parse of all 64 MB costs **0.37 s** (~170 MB/s), so ConPTY, not Flare, is the ceiling.
`cmd /c type bigfile` is 25 times slower (0.65 MB/s): a property of cmd, not of Flare. The floor in
the tests is therefore on responsiveness, completeness and the parse rate, not on ConPTY's rate.

**Keyboard (decision O2).** Slint 1.18 key events carry no scan code. winit does:
`slint::winit_030::WinitWindowAccessor::on_winit_window_event(|window, event| -> EventResult)`
(feature `unstable-winit-030`) sees `WindowEvent::KeyboardInput { event: KeyEvent { physical_key:
PhysicalKey::Code(KeyCode), logical_key, text, state, repeat, .. }, .. }`, `ModifiersChanged`,
`Ime(Ime::Commit(String))`, `MouseWheel { delta, .. }`; returning `EventResult::PreventDefault`
keeps Slint from also handling it. `format!("{:?}", KeyCode::KeyC) == "KeyC"` equals the W3C code
name Prism Terminal's `termKeys` compared (`code === 'KeyC'`), so Flare keeps PT's string
convention and its tests port 1:1. On Windows winit reports `text = Some("\u{3}")` for Ctrl+C; the
adapter drops `text` when Ctrl is down without Alt, so the encoder decides from the physical key.

## Decisions taken by the planner (not the owner)

1. **portable-pty with a preloaded absolute-path conpty.dll** (no own wrapper): see Verified facts.
2. **O3: no cursor-line carry; `resize_conpty` vertical re-anchor** (Task 20), test first, RED then GREEN.
3. **A byte `Scanner`** in front of `vte` for OSC (all) and `CSI > q`; events carry the byte offset
   after the terminator so replies are written in stream order (Task 14, Task 18).
4. **Bundled ConPTY files are committed** under `crates/flare-term/bundled/x64/` with a README
   (source, version, hashes) and `.gitattributes` binary; a test pins the sha256; the app build
   script copies them next to the exe (Task 1, Task 28); the installer (M9) ships them beside the exe.
5. **Key events are stringly like PT** (`key`, `code` W3C names) so `termKeys.test.ts` ports 1:1;
   the encoder is new (alacritty has none) and follows xterm's `ctlseqs` (Task 10).
6. **XTVERSION reply** is `ESC P > | Flare <flare version> (alacritty_terminal <version>) ESC \`
   (decision O17 + the open "confirm the name string" line). It never starts with `xterm.js`.
7. **DA1** `ESC[?6c` -> `ESC[?1;2c`; secondary DA and everything else alacritty answers stays.
8. **OSC 10/11 queries** are answered by Flare's own `colour_query_replies` (PT's tested function),
   not by alacritty's `ColorRequest` (ignored), so a list like `10;?;?` behaves as in PT.
9. **Wheel**: 3 lines per notch (`WHEEL_LINES_PER_NOTCH`), tuned by eye in M10; alt screen with
   alternate-scroll sends arrows; a program that owns the mouse gets SGR wheel reports.
10. **Plugin-env code lives in `flare-shells::env`** because `pty_env` takes it; its nine tests
    port here (test-port.md lists them under flare-agent; M6 ports only `isOurPlugin`).
11. **Tests deferred by test-port.md**: `termReplies` theme-push, `ThemeReports`, redraw-nudge and
    `linkColor` groups go to `flare-theme` (M4); `termPaste` `imagePasteKey`/`newlineKey` to
    `flare-agent` (M6); `openFolderDefault` to `flare-win` (M9). `nodePtyPin.test` is replaced by
    the bundled-DLL tests (Task 24).
12. **Two flags added to M1's `CellFlags`**: `DIM = 64`, `STRIKE = 128` (the u8 has room). M2 maps
    SGR 2 and 9 into them; the renderers paint them in M10 (recorded, not forgotten).
13. **Edition 2024** for the two new crates (let-chains allowed), as M1's crates.
14. **`openTermPath` is ported here, not in flare-win** (test-port.md splits termPathOpen.test.ts as "openTermPath and
    openFolderDefault in flare-win"): `open_term_path` takes its openers as a trait object, so it stays UI-free and its
    tests port with `resolveTermPath` and `pathKinds`; only `openFolderDefault` (the real Explorer call) waits for M9.
    Task 29 updates the test-port.md row to say so.
15. **Synchronized updates (DEC 2026) are let go by a per-handle timer** (Task 22), because `vte` only stores the
    150 ms deadline (Verified facts). Without it a program that never closes its update freezes the tab.

## Task 14: The byte scanner for OSC and CSI > q (Sonnet)

**Files:** `crates/flare-term/src/scan.rs`. Why: `alacritty_terminal` drops OSC 9, 52 (disabled), 10/11 queries, 777 and `CSI > q` inside `vte`
(Verified facts); Flare needs them. The scanner runs over every chunk **before** `vte`, never alters the bytes, and reports where each
sequence ended so the caller can feed `vte` up to that point, then act (replies in stream order, Task 18).

```rust
pub const OSC_MAX_BYTES: usize = 1_500_000;      // OSC 52 of 1 MB of text is ~1.4 MB of base64
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum ScanEvent {
    /// A complete OSC (introduced by ESC ], ended by BEL or ESC \). `payload` is everything between, e.g. b"9;9;C:\\x".
    /// `end` = index in THIS chunk just after the terminator.
    Osc { end: usize, payload: Vec<u8> },
    /// ESC [ > q  or  ESC [ > 0 q  (XTVERSION). `end` as above.
    Xtversion { end: usize },
}
pub struct Scanner { /* state, osc: Vec<u8>, csi: Vec<u8>, overflow: bool, limit: usize */ }
impl Scanner {
    pub fn new() -> Self;                         // limit OSC_MAX_BYTES; also impl Default
    pub fn with_limit(limit: usize) -> Self;
    pub fn scan(&mut self, chunk: &[u8]) -> Vec<ScanEvent>;    // keeps its state across chunks
}
```

State machine (states `Ground`, `Esc`, `OscBody`, `OscEsc`, `Csi`). Use `memchr::memchr` for `0x1b` in `Ground` and `memchr::memchr2`
for `0x07`/`0x1b` in `OscBody` so plain text costs almost nothing (1 MiB of `a` must scan in well under 5 ms in a release build).
- `Ground`: `ESC` -> `Esc`. `Esc`: `]` -> `OscBody` (clear payload, `overflow = false`); `[` -> `Csi` (clear csi); `ESC` -> stay `Esc`; anything else -> `Ground`.
- `OscBody`: `BEL` -> emit `Osc` (unless `overflow`) -> `Ground`; `ESC` -> `OscEsc`; `CAN` (0x18) or `SUB` (0x1a) -> abort to `Ground`;
  else push the byte (when payload is already `limit` long: set `overflow = true`, stop storing, keep scanning for the terminator).
- `OscEsc`: `\` -> emit `Osc` (unless overflow) -> `Ground`; `]` -> a new `OscBody` (the old one aborted); `[` -> `Csi`; `ESC` -> stay `OscEsc`...
  (an ESC that starts something other than ST aborts the OSC; treat the byte like `Esc` state would).
- `Csi`: bytes 0x20..=0x3f are collected (params, `>` prefix); a final byte 0x40..=0x7e ends it: if the collected bytes are exactly `>` or `>0`
  and the final is `q` -> emit `Xtversion`; -> `Ground`. `ESC` aborts and goes to `Esc`; `CAN`/`SUB` abort to `Ground`; other C0 controls (< 0x20) are ignored;
  more than 32 collected bytes -> abort to `Ground`.
- C1 single-byte introducers (0x9d) are not used (the stream is UTF-8). Bytes >= 0x80 in `Ground` are ignored.

## Task 16: Which paths on screen exist (Sonnet)

**Files:** `crates/flare-term/src/path_links.rs`. Source: `PT/core/renderer/lib/termPathLinks.ts` (read every comment: they record measured freezes) and `termPathLinks.test.ts`.
The JS module is global state with timers and callbacks. The Rust port is an owned struct with an explicit clock and **no callbacks**:
operations that used to call listeners return the owners to wake. The pty-facing side asks in pieces: `take_ask` hands out ONE piece (<= 300 paths) at a time and

pub const ANCHORS_MAX: usize = 4; pub const ANCESTORS: usize = 4; pub const TAUGHT_MAX: usize = 256;

#[derive(Clone, Debug, PartialEq, Eq)] pub struct LinkRange { pub start: usize, pub end: usize, pub path: Option<String> } // path None = a web link
#[derive(Clone, Debug, PartialEq, Eq)] pub struct Ask { pub base: String, pub paths: Vec<String> }                         // one piece
#[derive(Clone, Debug, PartialEq, Eq)] pub enum Found { Hit(PathFound), No, Unknown }
pub fn holds_cwd(dir: &str, cwd: &str) -> bool;            // norm = '/'->'\', strip trailing '\', lower-case; cwd == dir || cwd starts with dir + "\"
pub fn parent_dir(dir: &str) -> Option<String>;            // strip trailing separators; no separator -> None; the part before the last one; "X:" -> None
pub fn path_candidates(text: &str) -> Vec<PathCandidate>;  // find_paths minus: followed by '>' (a prompt), or overlapping a web link

impl PathLinks {
    pub fn new() -> Self;                                  // + Default
    pub fn subscribe(&mut self, owner: &str); pub fn unsubscribe(&mut self, owner: &str);
    /// Port of linkRanges: web links, then path candidates known to exist from `cwd` (or, for a RELATIVE path, from the folders the
    /// owner has shown, `find_path`); unknown ones are queued for `owner` (and `asked` is set). No cwd -> only web links. Text with none
    /// of [\\/.] -> only web links. An ABSOLUTE path that exists teaches its folder (`learn_anchor`). Sorted by start.
    pub fn link_ranges(&mut self, text: &str, cwd: Option<&str>, owner: &str, now_ms: u64) -> Vec<LinkRange>;
    pub fn take_asked(&mut self, owner: &str) -> bool;     // reads and clears
    /// Moves queued asks to ready once BATCH_MS has passed since the first queued one; returns owners whose deferred "taught a folder"
    /// wake is due (a wake for a folder is deferred to the NEXT advance, the old setTimeout 0), only subscribed owners, each once.
    pub fn advance(&mut self, now_ms: u64) -> Vec<String>;
    /// The next piece to send, or None when one is in flight or nothing is ready. Marks its keys in flight (later askers join).
    pub fn take_ask(&mut self) -> Option<Ask>;
    /// `hits` = the host's answer for `ask` (same order). None = unanswered: nothing is cached, the keys leave flight (asked again on the next paint).
    /// Some(empty) = REFUSED: every path is cached as "no". Some(short list): indices past its end are not cached. Returns the subscribed
    /// owners of the paths that turned out to exist (deduplicated). Clears the cache when it exceeds MAX_ENTRIES before inserting.
    pub fn answer(&mut self, ask: &Ask, hits: Option<Vec<Option<PathHit>>>, now_ms: u64) -> Vec<String>;
    pub fn find_path(&self, owner: &str, cwd: &str, path: &str, now_ms: u64) -> Found;
    pub fn forget_owner(&mut self, owner: &str);           // anchors, taught, asked, queued and in-flight owner entries
    pub fn owners_kept(&self) -> usize;                    // |anchors ∪ taught ∪ asked|
}

`find_path` (port of findPath): known from cwd -> `Hit{hit, base: cwd}`; unknown from cwd -> queue it and `Unknown`; known "no" and the path is absolute (`^(?:[A-Za-z]:|[\\/]|~)`) -> `No`;
relative: for each base in `anchor_bases(owner, cwd, path)`: a known hit counts unless it is a DIR that `holds_cwd(abs, cwd)`; an unknown base is queued and makes the answer `Unknown`; else `No`.
`anchor_bases`: for each anchor of the owner (newest first, <= ANCHORS_MAX): walk up to `climb` parents (climb = ANCESTORS when the path has a separator, else 0), skipping a folder equal to `cwd` (case-insensitive) and duplicates.
`learn_anchor(owner, hit)`: dir = hit.abs for a Dir else `parent_dir`; already first -> nothing; else prepend, keep ANCHORS_MAX; and ONCE per (owner, dir) in its life (`taught`, capped at TAUGHT_MAX) schedule a deferred wake for the owner.
A cached "no" older than NO_TTL_MS is treated as unknown; a "yes" stays. Cache key = `cwd + "\n" + path`.

```rust
use alacritty_terminal::{grid::Dimensions, index::{Column, Line, Point}, term::{Term, TermMode, cell::{Cell, Flags}}, vte::ansi::Color, event::EventListener};
use crate::emulator::Dims;

fn is_blank(c: &Cell) -> bool {
    (c.c == ' ' || c.c == '\0') && !c.flags.contains(Flags::WIDE_CHAR_SPACER) && c.zerowidth().is_none()
}
/// Every screen row below the cursor line is blank (the "no text below" test PT used before its carry).
fn rows_below_cursor_blank<T>(term: &Term<T>) -> bool { /* for line in cursor.line+1 .. screen_lines, all cols is_blank */ }

/// Where ConPTY will have the cursor row after the resize. ConPTY reflows ONLY the old screen rows, keeps the viewport top fixed, and
/// leaves blank rows at the bottom; alacritty keeps the cursor row fixed instead. Group the old screen rows into logical lines (a row whose
/// last cell has WRAPLINE continues into the next). For the logical lines ABOVE the cursor's line: each takes
/// max(1, ceil(trimmed_len / new_cols)) rows, trimmed_len = (row - start) * old_cols + col + 1 of its last non-blank cell (0 for an empty row).
/// The cursor's own line adds offset / new_cols rows, offset = (cursor_row - start) * old_cols + cursor_col. The sum is clamped to rows - 1.
fn conpty_cursor_row<T>(term: &Term<T>, new_cols: usize, new_rows: usize) -> usize;

pub fn resize_conpty<T: EventListener>(term: &mut Term<T>, cols: usize, rows: usize) {
    let old = (term.columns(), term.screen_lines());
    if old == (cols, rows) { return; }
    let alt = term.mode().contains(TermMode::ALT_SCREEN);
    let target = if !alt && rows_below_cursor_blank(term) { Some(conpty_cursor_row(term, cols, rows)) } else { None };
    term.resize(Dims { cols, rows });
    let Some(r_t) = target else { return };
    let r_a = term.grid().cursor.point.line.0.max(0) as usize;       // where alacritty put the cursor row
    if r_t > r_a {
        // ConPTY kept more of the top: pull rows back out of history. Growing the line count pulls from history and
        // moves the cursor down; shrinking it back drops the (blank) bottom rows.
        let pull = (r_t - r_a).min(term.grid().history_size());
        if pull > 0 { term.resize(Dims { cols, rows: rows + pull }); term.resize(Dims { cols, rows }); }
    } else if r_a > r_t {
        // ConPTY has the cursor higher: push the extra top rows into history, blank rows appear at the bottom.
        let k = r_a - r_t;
        term.grid_mut().scroll_up::<Color>(&(Line(0)..Line(rows as i32)), k);
        term.grid_mut().cursor.point.line = Line((r_a - k) as i32);
    }
}
```

Behaviour (each line is a PT rule with its source; the tests below pin them):
- **Spawn** (terminal.ts spawnTerm/spawnPending): under one mutex: refuse when `sessions` or `pending` has the id; add to `pending`; on every exit path remove from `pending` and `killed_while_pending`.
  `def = shell_by_id(shell_id, &shells.shells())` (None -> false); then check `killed_while_pending`. Adopt a warm shell only if `resume.is_none()`, the entry for `root.to_lowercase()` exists, is not exited,
  has `def_id == def.id` and `plugin_key == plugin_key(plugin)`. Otherwise launch: `Launch` = `with_resume(def, resume)` when a resume id is given, else the def; env = `pty_env(<process env>, Some(def.id), plugin, None, Some(token))`
  plus `launch.env`; `token` = `uuid::Uuid::new_v4().simple().to_string()` (one per shell, warm or not, carried to the tab that adopts it); size = the desired size of `id`, else of the warm slot `""`, else 80x24;
  `cwd = root`. After the spawn, if `killed_while_pending` has the id: kill the new process (as in `kill`) and return false, registering nothing.
- **IO threads per session** (reader, pump, writer): reader loop `read(64 KiB)` -> `output_ticks += 1` -> push into the session's `OutputBatcher` under a mutex (block while the batcher holds >= `backlog_max`, so a flood throttles the shell instead of growing memory); pump thread waits on a Condvar with `due_in`, `take_due`, `sink.data(id, bytes)`; writer thread drains an mpsc channel into the pty writer.
  Output is coalesced every 8 ms and **a batch is flushed before the exit message**. On reader end-of-file or error: close.
- **Exit** (rule: ConPTY gives NO end-of-file when the shell exits): `proc.on_exit(cb)`; the callback runs a short finisher thread: wait until the batcher has been idle for `exit_grace` (max 1 s), drop the pty (ClosePseudoConsole, which ends the reader), join reader, flush, `sink.data` for the rest, `sink.exit(id, code)`, remove the session if it is still THIS session (compare a per-session `u64` token, not the id).
- **Kill** (terminal.ts killTerm/killPty): `killed_while_pending.insert(id)` if the id is pending; remove the session from the map FIRST (a late exit is then a no-op), forget `desired_size`, then `kill_pty`: increment `dying`, spawn a killer thread that calls `proc.kill()`, then drives an `ExitPoller` (read `exit_code()` every 20 ms for 5 s, then every second; on `Stuck` log `kill-stuck` once with `log::warn!`; never gives up), then drops the process, joins the reader/pump/writer threads, decrements `dying` and notifies the Condvar behind `shells_gone`. No flush, no sink calls after a kill (the death is ours).
- **Warm shells** (prewarm, spawnPending; rule 30): at most `warm_max` (2), one per `root.to_lowercase()`. `prewarm`: a held entry with another `plugin_key` is killed first; an existing matching entry returns; if the slot count is already `warm_max`, EVICT the others (remove, dispose, kill if not exited) until there is room; then spawn at the `""` desired size (default 80x24) and keep its output (up to `warm_banner_cap` bytes) in a buffer; replace the slot. The warm entry's exit marks it `exited` and removes it **only if the stored entry's token equals this one** (the 2026-09-24 bug: a handler that outlived the adoption deleted the NEXT warm shell). Every eviction and every `kill_warm` kills (never merely forgets). Adoption replays the buffered banner to the sink as the first `data`, then the session behaves like any other (the same threads keep running; flip the pump's destination from "buffer" to "sink" under the mutex).
- **Resize** (terminal.ts resizeTerm): `cols < 2` or `rows < 1` is ignored; remember `desired_size[id]`; no session yet -> return (the spawn will be born at that size); on `Err` from the pty, retry up to `resize_retries` times every `resize_retry_delay` (a timer thread or a short sleep loop on a helper thread), each time only while that size is still the desired one.
- **cd** (decision O1): never marks anything as typed (the manager knows nothing of typing).
- **No blocking call on the caller's thread** except `spawn` and `prewarm`, which document it. Every `join`, `recv`, `wait`, `sleep` carries `// sync-ok: <why it is on a worker>`.

The `SessionSink` the handle registers: `data(id, bytes)` splits the bytes in slices of at most 64 KiB, and for each slice takes `emu.lock()` (the FAIR lock, so the UI's `snapshot` gets its turn between slices),

**The sync timer** (Verified facts, DEC 2026): after each `data` call, still in the sink, read `emu.lock().sync_deadline()`. When it is `Some`
and the handle's `sync_armed: AtomicBool` was false (`!sync_armed.swap(true)`), spawn ONE short-lived thread holding a `Weak` of the handle's

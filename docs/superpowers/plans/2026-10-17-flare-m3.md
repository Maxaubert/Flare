> Workflow, one `agent()` per task, waves in parallel). Steps use checkbox (`- [ ]`) syntax. Every
> task is TDD: write the failing test, run it and see it fail, implement, run it and see it pass,

> **Staging rule (parallel builders share ONE worktree):** stage only the files your task lists
> (`git add <exact paths>`, never `git add -A` or `git add .`, never `git commit -a`), commit only
> those, and never touch another task's files. **Only Task 1 and the orchestrator edit any

> Cargo serialises on the target-dir lock, so a build may wait a minute; that is normal, do not kill it.
> `cargo nextest run -p <crate> <filter>` while iterating, the whole workspace only in Task 35.
> **A build error in a file your task does not own** (another builder is mid-edit; `flare` compiles every
> crate, and every Slint file is compiled by `crates/flare/build.rs`) is not yours to fix: wait two minutes

> compiles its own file at once (`cargo build -p flare`) and commits only when that passes.

## Global Constraints

Copied from the roadmap and M2; every task obeys them.

- **Security (added by the orchestrator after M2's security review, 2026-10-17):** a folder that a
  tab learned ONLY from a program's OSC 9 report is never used to spawn, restore or stat when it is a
  UNC path (`\\host\share`) or contains any control character: Windows would connect over SMB and
  could leak the user's NTLM hash. Restore uses the tab's last local folder instead; an explicit user
  action (the + menu, typing `cd`) is what may take a tab to a share. The restore task gets a test:
  `restore_never_spawns_in_a_reported_unc_folder`.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes** anywhere (code comments, docs,
  test strings, UI copy); CI greps for them.
- Flare's own names only: profile `%APPDATA%\Flare` (files `tabs.json`, `window.json`, `settings.json`),
  lock name from Task 15, window class `Flare.SessionEnd`, setting keys `flare.*` (decision O10). Never a
  Prism name in an identifier, path, key or string (README and docs may name Prism Terminal as the source).
- **Every display scaling works** (roadmap, owner 2026-10-17: 100, 125, 150, 175, 200, 225, 250 and 300
  percent, both renderers, moving between monitors). For this milestone that means: every length that is
  an edge between two surfaces, a hairline or a tab boundary is a whole number of device pixels (Tasks 6,
  19, 20, 21); hairlines are `max(1, floor(scale))` device pixels, which is what Chromium drew for
  Prism Terminal; every geometry test runs at the eight scales; the screenshots are taken at 100, 150 and
  225 (Task 33).
- New dependency = a reason line in `README.md`'s dependency list and a `THIRD-PARTY-NOTICES.md` entry in
  the same PR (Task 35); `cargo deny check` passes. Pin with `=`. Every `pub fn new() -> Self` with no
  arguments also gets `impl Default`.
- CI gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo nextest run --workspace`, `cargo deny check`.
- Nothing in tests may open a visible window, take the foreground, touch the real clipboard or the real
  `%APPDATA%\Flare`. Tests that need a folder use `tempfile`; tests that start a shell reap it (M2's
  `Guard`). UI tests use the headless software platform (Task 19b's harness) only.
- **UI thread never waits (rule 34).** `std::fs` on a live path, process starts, folder stats and the
  folder picker run on worker threads; any blocking call in non-test code in `flare-tabs`, `flare-settings`,
  `flare-win` or `flare` carries `// sync-ok: <reason>` on the same line (startup read of the two state
  files, the quit flush, tests) and the scan test of Task 35 enforces it.
- **One state, one place (rule 44):** the used list, the walk, placeholders, recents and pins live in the
  window model or the settings file; persisted: `tabs.json`, `window.json`, recents, pins, stored choices.
  Tabs are never imported from Prism Terminal (rule 46).
- **Tab reports are ignored until the first restore has answered** (rule 37): `TabModel::saved()` is not
  written before `restore_done`.
- **Closing the window quits; closing the last tab does not** (rule 27); the quit waits for every shell,
  3 s cap, on the child's exit code (rule 28; M2's `shutdown`).
- **The only thing ever typed into a shell by this milestone is nothing:** the restore passes the resume
  as the startup command through M2's `StartOptions.resume`; M3 adds no write path (rule 2).
- Builders: Haiku by default, Sonnet where marked. Reviews: Opus. Never Fable.
- The PR reports test counts, the screenshots (Task 33) and the Opus findings.

## Review Focus

- **Single instance** (Task 15, 29, 34): the lock and the pipe are keyed by the profile folder, so an e2e
  run (its own profile) never hands its folders to the owner's running Flare; a second launch hands over
  and exits 0 even when it starts while the first is still creating its window; the first raises its window
  (the second calls `AllowSetForegroundWindow` first). Opus runs two instances by hand.
- **Quit and state** (Task 29, 34): every route out of the window ends at one close handler; tabs.json and
  window.json are flushed synchronously there and at session end; a veto leaves the window open; the quit
  waits for every shell. Check nothing writes `tabs.json` before the restore answered.
- **Restore** (Tasks 13, 18, 27): placeholders at the first frame, settled in place, a placeholder closed
  before the answer spawns nothing, the front tab rule, every restored shell spawned at restore time, the
  resume hook point (`SessionLookup`, `StartOptions.resume`) is the ONLY route to an agent resume.
- **Display scaling** (Tasks 6, 19 to 21, 33): look at the 100 / 150 / 225 screenshots tab by tab: no
  blurry edge, no 1.5 px line, the active rule and dividers crisp, tab labels centred, nothing clipped.
- **Keys** (Tasks 10, 28): one chord table feeds the window filter and the terminal's "owns this key" check;
  a chord never reaches the pty; under a question every chord but close-tab is swallowed; Ctrl+Tab in
  Most recent mode commits on Ctrl release.
- **Sidebar slide** (Tasks 11, 21, 30): the terminals are not resized per frame; one fit at the end.

## Verified facts (2026-10-17; prototype `scratchpad\proto3`, built in the shared target dir, run on this PC)

**Slint 1.18.1 (all compiled and RUN headless with `MinimalSoftwareWindow`):**
- `cubic-bezier(...)` needs a leading zero on every number: `cubic-bezier(0.16, 1, 0.3, 1)` compiles,
  `cubic-bezier(.16,1,.3,1)` is a syntax error. Prism Terminal's curves: slide `0.16, 1, 0.3, 1` (240 ms),
  carry `0.23, 1, 0.32, 1` (170 ms).
- `x: item.x * 1phx;` with an `int` field of a model struct compiles and places an element on an exact
  device pixel. `floor(1px / 1phx)`, `round(l / 1px * scale)`, `max(1phx, ...)` compile.
- **A `global` cannot use `phx`** ("Cannot convert between logical and physical length in a global
  component"). So the device-pixel helper is `global Px { in-out property <float> scale: 1.0;
  pure public function snap(l: length) -> length { return round(l / 1px * scale) / scale * 1px; } }`
  with `Px.scale` set from the window (`out property <float> win-scale: 1px / 1phx;`, `changed win-scale
  => { Px.scale = root.win-scale; }` and `init`). `snap(2px)` at 2.25 gives 2.2222 px (5 device pixels).
- **A hairline of `max(1phx, floor(1px / 1phx) * 1phx)` measured 1 device pixel at 100% and 150% and 2 at
  225%** (the Chromium rule Prism Terminal's `1px` borders obeyed). A plain `1px` would be 1.5 device pixels
  at 150% and blur.
- `TouchArea { pointer-event(e) => { ... } }` delivers `e.kind` (`PointerEventKind.down/up/move/cancel`) and
  `e.button` (`PointerEventButton.left/right/middle`); headless `WindowEvent::PointerPressed/Released/Moved`
  with `PointerEventButton::Left/Middle/Right` reach it. `ta.mouse-x`, `ta.pressed-x`, `ta.has-hover` work;
  the `moved` callback fires while pressed. `WindowMoveArea { }` compiles inside a `Rectangle`.
- `Text { overflow: elide; horizontal-alignment: center; }` elides with an ellipsis and centres.
- `animate x { duration: 170ms; easing: cubic-bezier(...); }` runs on the platform clock: a headless
  `Platform::duration_since_start()` returning a settable value plus `slint::platform::
  update_timers_and_animations()` advances it (measured: x 0 to 200 over 240 ms, 165 at 60 ms, 194 at 120 ms).
  Without a clock override animations never move in a headless test; Task 19b's harness provides one.
- **`set_platform` is per thread**: three threads each set their own `MinimalSoftwareWindow` platform, create
  an `AppWindow` and got one click each. UI tests therefore run under plain `cargo test` and nextest alike.
- `StyledText { text: @markdown("**bold** words"); }` compiles; **`@markdown` takes only a literal**
  (`@markdown("**{}**", who)` is a syntax error). Dynamic styled text comes from Rust. **Checked in the local
  registry source (`i-slint-core-1.18.1/styled_text.rs`, `i-slint-compiler-1.18.1/builtin_elements.rs`,
  review 2026-10-17):** `slint::StyledText::from_plain_text(&str) -> StyledText` and
  `slint::StyledText::from_markdown(&str) -> Result<StyledText, slint::StyledTextFromMarkdownError>`; the Slint
  property type is `styled-text`; the `StyledText` ELEMENT has `text: styled-text`, `default-color: brush`,
  `default-font-size: length`, `default-font-family: string`, `horizontal-alignment`, `vertical-alignment`,
  `max-lines`, `link-color` (it is not experimental). **Per-span colour IS supported** through the inline HTML tag
  `<font color="#rrggbb">...</font>` (hex `#rgb`, `#rrggbb`, `#rrggbbaa` or a CSS colour name; parsed by
  `i-slint-common/styled_text.rs`), and `<u>` underlines.
- **Every exported component that inherits `Window` gets generated Rust code** (`i-slint-compiler` `exported_roots`;
  a non-Window export only warns). So `app.slint` can re-export several preview windows
  (`export { TabStripPreview } from "tabs.slint";`) and each becomes a Rust type next to `AppWindow`.
- **`slint::platform::set_platform` answers `AlreadySet` the second time on the SAME thread** (its context is a
  thread-local `OnceCell`). A test that builds two harnesses on one thread must reuse the thread's platform
  (Task 19b does). libtest and nextest both run each test on a fresh thread.
- **A repeater keeps its instances only while its model does**: replacing `tab-rows` with a new `ModelRc` destroys
  every row's `TouchArea`, and with it a pointer grab in progress (a carry would end mid-drag). The tab rows are ONE
  `slint::VecModel<TabRow>` set once; updates go through `set_row_data` (Task 26 `sync_rows`).
- `slint::BackendSelector::with_winit_window_attributes_hook(Fn(WindowAttributes) -> WindowAttributes)` exists with
  the `unstable-winit-030` feature (`i-slint-backend-selector-1.18.1/api.rs`); winit 0.30.13 has
  `WindowAttributes::with_active(bool)`, `with_visible(bool)` and, on Windows,
  `winit::platform::windows::WindowAttributesExtWindows::with_skip_taskbar(bool)` (Task 30b uses them for `--e2e`).
- Slint offers `KeyBinding`, an experimental FlexboxLayout and drag-and-drop, none used here: chords go
  through the winit filter (physical keys, M2 decision O2) and the tab strip is laid out in Rust.
- Everything M1 and M2 verified still holds: `no-frame` windows get resize borders from the winit backend,
  `WindowMoveArea` moves the window on press-and-drag and lets a plain click through to child `TouchArea`s,
  `on_winit_window_event` (feature `unstable-winit-030`) sees `KeyboardInput`, `ModifiersChanged`,
  `CursorMoved`, `MouseWheel`, `Ime` and also `DroppedFile`, `HoveredFile`, `HoveredFileCancelled`.

## Decisions taken by the planner (not the owner)

D1. **A new crate `flare-tabs`** holds the pure tab logic. `docs/test-port.md` maps these tests to "flare"
   (the binary), but a binary crate drags Slint, wgpu and a window into every `cargo test`; the roadmap says
   logic lives in small UI-free crates. Task 35 updates the ledger rows.
D2. **`PrefStore` in `flare-settings`** (a string key/value store with change listeners, a `MemoryBackend`
   for tests and a `FileBackend` over `settings.json`) replaces Prism Terminal's `localStorage` reads and
   writes one for one, so every ported test keeps its shape ("junk reads the default", "never stores junk",
   "blocked store"). M7 builds the settings pages and the PT import on it. Keys are `flare.*` (O10):
   `flare.window.tabLayout`, `flare.window.tabSwitch`, `flare.window.sidebar`, `flare.window.sidebarWidth`,
   `flare.newtab.mode`, `flare.newtab.folder`, `flare.recentRoots`, `flare.pinnedRoots`, `flare.term.shell`,
   `flare.window.agentKeys` (PT `prism.window.agentKeys`, bool, default on: the agent hotkeys of the chord table).
D3. **`window.json` stores width and height in logical pixels, x and y in physical pixels, and the scale it
   was saved at** (`{"width":1180,"height":780,"x":..,"y":..,"maximised":false,"scale":1.5}`; `scale` absent
   reads 1.0). Prism Terminal used Electron's DIPs everywhere; physical positions are the only unambiguous
   thing across monitors of different scales. The on-screen check multiplies the size by the saved scale.
D4. **Single instance = a named mutex plus a named pipe, both keyed by a hash of the profile folder**
   (Task 15). Not WM_COPYDATA: it needs a window to find and a message pump thread of its own; the pipe is
   a plain byte stream and the e2e's per-scenario profiles get their own lock for free (an Electron
   `userData` lock did the same for Prism Terminal).
D5. **Tab geometry is computed in Rust in device pixels** (`strip_layout`, Task 6) and Slint only places
   rectangles at `x * 1phx`; the browser snapped flex boxes to device pixels for Prism Terminal and Slint
   does not.
D6. **The +N button is a fixed 72 px box** (`MORE_BUTTON`), the width `planStrip` already budgets; Prism
   Terminal's was content-sized. The dots and the chevron fit inside it. (Visible difference: none at
   one to four dots.)
D7. **The close question's body colours the names (the agent and the tab) with the text ink, as Prism Terminal
   did**, through `StyledText` and the inline `<font color="#dedacf">..</font>` tag (verified: Slint 1.18.1's
   styled text supports per-span colour); the rest of the body is `default-color: Theme.dim`. The ink is
   `flare_tabs::close_flow::NAME_INK` (`#dedacf`, `Theme.text` of `pt-default`; M4 passes the theme's value). The
   scrim is the same 50% black without the 2 px backdrop blur (Slint has no backdrop blur): a question for the
   owner (below).
D8. **Hairlines and one-pixel edges are `max(1, floor(scale))` device pixels** (measured, Verified facts).
D9. **While the sidebar slides, the terminal keeps its size** (rule: fit once at the end): the grid image
   keeps its frozen width and is clipped, the sidebar slides over its left edge; at the end of the hold one
   resize reaches the terminal (`FitHold`, Task 11). Under see-through (M4) the page cut under a slid-out
   sidebar is M4's job; M3 draws the slid-out sidebar opaque.
D10. **Marks and agent icons are M6's.** M3 draws the shell prompt glyph and the cog as tab icons, the
   loading ring of a tab coming back, and leaves a mark slot in every row (`mark-kind`, `mark-color`)
   that M6 fills. `TabModel::set_agent` is the hook M6 calls; `SessionLookup` is the hook for finding a
   Claude session (M3 ships `NoSessions`).
D11. **The Settings tab's body is a placeholder** until M7 (centred "Settings" in the dim ink); the tab,
   its label, its toggle (cog, Ctrl+,, the start screen row) and its "never persisted" rule are real.
D12. **Folder drops:** a path dropped on the tab row or the sidebar opens a new tab in its folder (a file
   opens the folder that holds it); a drop over the terminal is M5's (typed quoted path). The strip stops
   being a window-drag handle while a drag hovers the window.
D13. **`--user-data-dir=<path>` and `--e2e`** are parsed now (the e2e harness of M10 launches
   `flare.exe --user-data-dir=<profile> --e2e`): the first moves the profile folder, the second shows the
   window inactive, never raises it, makes it unfocusable and keeps it off the taskbar.
D14. **Placeholders of a tab coming back to an agent show the bare ground** (the resume skeleton is M6) and
   the loading ring at the tab's end.

```rust
// atomic.rs
/// Writes `<file>.tmp` then renames it over `file` (Windows replaces in one step): the file is always the
/// old one or the new one, never half of either.
pub fn write_atomic(file: &Path, data: &str) -> io::Result<()>;
pub struct AtomicWriter { /* Arc<Inner>: file, seq AtomicU64, next Mutex<Option<(String, u64)>>, running, landed Mutex<u64>, pause */ }
impl AtomicWriter {
    pub fn new(file: impl Into<PathBuf>) -> Self;
    /// Test seam: the background job sleeps `pause` between writing the temp file and renaming it.
    pub fn with_pause(file: impl Into<PathBuf>, pause: Duration) -> Self;
    /// Never blocks. A background thread writes `<file>.tmp`, then renames it only if no newer write has
    /// landed (`landed` is locked across the check and the rename). Of a burst only the newest is written.
    /// An io error is swallowed (the previous file stays; the next save tries again), one `log::warn!`.
    pub fn save(&self, data: String);
    /// Synchronous: `<file>.now.tmp` then rename; sets `landed` to its own number, so an older job in
    /// flight never lands over it. The close, quit and session-end path.
    pub fn save_now(&self, data: &str) -> io::Result<()>;
    /// Waits until the background queue is empty (tests and the quit).
    pub fn idle(&self);
}
// debounce.rs
pub struct Debounced { /* Arc<Inner>: AtomicWriter, Mutex<State{pending: Option<String>, deadline: Option<Instant>}>, Condvar, stop; one worker thread */ }
impl Debounced {
    pub fn new(file: impl Into<PathBuf>, delay: Duration) -> Self;
    /// pending = data; the wait restarts (PT: clearTimeout then setTimeout).
    pub fn save(&self, data: String);
    /// Pending data is written NOW with `save_now`; nothing pending leaves the file alone.
    pub fn flush(&self);
    /// The save still inside its delay (it IS the newest state: a load inside the 400 ms must see it).
    pub fn pending(&self) -> Option<String>;
    pub fn idle(&self);
}
// Drop stops the worker and writes nothing.
```

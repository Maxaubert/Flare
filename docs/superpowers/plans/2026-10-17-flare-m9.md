# Flare Milestone 9: Updates, installer, Explorer verbs, diagnostics log, icon, release (detailed plan)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (run as a
> Workflow, one `agent()` per task, waves in parallel). Steps use checkbox (`- [ ]`) syntax. Every
> task is TDD: write the failing test, run it and see it fail, implement, run it and see it pass,
> commit. Each task names its model: **Haiku** unless marked **Sonnet**. Opus only reviews (Task 41
> and the whole-milestone review).
> **Every cargo command takes `--target-dir <TARGET>`**, where `<TARGET>` is the folder the
> orchestrator names in your task prompt (one folder per builder, never `target` and never another
> builder's folder). That includes `cargo build`, `cargo nextest run`, `cargo clippy`, `cargo run`,
> `cargo test --doc`. `cargo fmt --check` and `cargo deny check` build nothing and take none. The first
> build in a fresh target folder compiles the whole tree (Slint, wgpu, now Velopack): the orchestrator may
> seed a folder by copying a warm one before the wave starts; a builder never kills a running build.
> **Staging rule (parallel builders share ONE worktree):** stage only the files your task lists
> (`git add <exact paths>`, never `git add -A` or `git add .`, never `git commit -a`), commit only
> those, and never touch another task's files. **Only Task 1 and the orchestrator edit any
> `Cargo.toml`, any `lib.rs` or `mod.rs`, `main.rs` module lists, `build.rs`, `ui/app.slint`'s import and
> re-export lines, `.cargo/config.toml` or `.github/workflows/*`** (Task 1 creates every module file with a
> `//!` line, lists them all, and adds every dependency and feature below, so nobody else needs to; the workflow
> files have one owner each: Task 28 `release.yml`, Task 37 `installer-e2e.yml`, Task 38 `update-e2e.yml`). A task that needs a new dependency, module or struct tells the
> orchestrator, who edits in one commit between waves. `cargo nextest run -p <crate> <filter> --target-dir
> <TARGET>` while iterating, the whole workspace only in Task 42.
> **A build error in a file your task does not own** (another builder is mid-edit; `flare` compiles every
> crate and `crates/flare/build.rs` compiles every Slint file) is not yours to fix: wait two minutes and
> build again; after three tries report it to the orchestrator. Never edit, stash or revert another task's
> file. A Slint task compiles its own file at once (`cargo build -p flare --target-dir <TARGET>`) and commits
> only when that passes.
> **Same-file runs go one after the other, never together:** Tasks 30, 31 and 32 (they all edit `appctl.rs`,
> `window.rs`, `startup.rs`, `main.rs` or `app.slint` wiring) run in that order. Tasks 14, 15, 16 run in that
> order (each builds on the previous file's functions). Tasks 4 to 13 and 17 to 23 each own different files and
> run together.
> **The one exception to the `build.rs` rule is Task 26** (it adds the resource generation below Task 1's compile
> call); no other wave-2 task edits `build.rs`, and Task 26 builds once at once after its edit so a broken
> `build.rs` never sits in the tree while Tasks 24 and 25 compile.
> **Integration tests (`crates/*/tests/*.rs`) do not see `#[cfg(test)]` items of the library.** Anything such a
> test needs (fakes, clocks, test hooks) is plain `pub` (with `#[doc(hidden)]` for hooks), never `#[cfg(test)]`
> and never behind a cargo feature; a test that needs private access goes in the module's own
> `#[cfg(test)] mod tests` block instead.
> **Never "fix" a golden vector or a Prism Terminal number by changing the expectation.** The fixtures
> (Task 2) are Prism Terminal's own code answering; if Flare disagrees, Flare is wrong. The only exceptions
> are written into the task that has them (Task 4: three exotic version strings) and listed in the report.
> **No em-dashes anywhere** (code, comments, docs, UI copy, YAML, PowerShell, test strings). CI greps for them.

**Goal:** Flare can be shipped, updated and lived with. Seven things, each ported from Prism Terminal
v0.55.6 (the parity target) and re-expressed natively:

1. **Velopack packaging.** A per-user, one-click installer (`Flare-win-Setup.exe`), a portable zip, full and
   delta packages and a `releases.win.json` feed, built by `vpk pack` from the release build, tagged
   `v<version>`, attached to the releases of the private repo by a GitHub Actions workflow on `windows-latest`.
2. **The update check and install logic**, built and tested end to end against a fake feed and against real
   packages, **compiled out of the shipped binary by a cargo feature (`live-updates`, off) until the owner
   makes the repo public.** Install only what was offered; the close question pre-answered at the quit;
   cancel leaves nothing.
3. **The update chip and the update window** in Slint, pixel-matched to Prism Terminal's (`UpdateChip.tsx`,
   `UpdateDialog.tsx`), at all eight display scalings, with the release-notes parser and grouping ported
   against Prism Terminal's own code (golden vectors).
4. **Explorer verbs "Open in Flare"**: two per-user registry keys written through the registry API (folder and
   folder background), the Settings row from M7 becomes live, default on, the one stored fact is the NO,
   relabel on launch, removed by the Velopack uninstall hook.
5. **The diagnostics log** `%APPDATA%\Flare\logs\diag.jsonl`: an asynchronous writer (batch, rotate at 2 MB
   keeping four, queue cap, never throws), the error gate, a native stall watchdog (O16), the memory watch,
   panic hooks, the session line and the crumbs, behind M6's `DiagSink` and M7's `DiagControl`; and the reader
   tool (`cargo diag`, the `npm run diag` of Flare) with golden output from Prism Terminal's `tools/diag.mjs`.
6. **PRIVACY.md**, the app icon pipeline (`tools/make-icon.py`, placeholder mark, O17) and the exe's embedded
   icon and version resource.
7. **The side-by-side proof.** An e2e scenario installs Flare beside Prism Terminal and shows no shared lock,
   profile, verb, plugin or signal.

Every Prism Terminal v0.55.6 unit test that `docs/test-port.md` maps to these areas is ported (ledger in

## Global Constraints

Copied from the roadmap and M2 to M8; every task obeys them.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes.** Flare's own names only: nothing in
  Flare's own identifiers, paths, keys, registry values, UI strings or file names says Prism, except the
  allowed places in Task 35 (`crates/flare-settings/src/import/`, doc comments that say "Prism Terminal" as
  the source, the test fixture `names.json` and the e2e neighbour). Every Flare name is a constant in
  `crates/flare-win/src/names.rs` (Task 1 writes it, Appendix B lists it).
- **Every display scaling works** (owner, 2026-10-17: "it has to work on all sorts of different DPI scalings,
  like 150 or 200 percent"): 100, 125, 150, 175, 200, 225, 250 and 300 percent, both renderers, and moving the
  window between monitors of different scalings. For this milestone: the chip, the notice under it and the
  update window are laid out by `flare_update::geom` in logical pixels whose EDGES are snapped to whole device
  pixels (the chip's left and right edge, its fill, the hairline of the notice, the window box edge, the
  progress track and its fill, the button boxes). The chip's width never changes across the phases at any
  scale. Rust recomputes the geometry on every scale-factor change (the M3 `Px.scale` signal). Task 33 tests
  all eight scales on the software renderer and on the GPU renderer where an adapter exists.
- **The updater is built, tested and switched OFF** (owner, 2026-10-17): `live-updates` is a cargo feature of
  `flare-update` and `flare`, absent from `default`, absent from the release workflow until the repository
  variable `FLARE_LIVE_UPDATES` is `on`. Without it the shipped binary contains no code path that creates a
  network source and starts no checking thread (Task 10, Task 35 scans). The preview (`--preview-update`)
  never needs the feature: it touches nothing. **The release workflow refuses to build the feature while the
  repository is private** (it asks `gh repo view --json visibility` and fails the run when the variable is `on`
  or a `default` feature list names `live-updates` and the answer is not `PUBLIC`; Task 28), so neither the
  variable nor a premature `default` flip can ship a live updater from the private repo.
- **Installers are attached to the private repo's releases meanwhile; the owner installs them by hand.** Nothing
  in the milestone installs anything on this PC: local packaging is `vpk pack` into a temp folder and the
  portable zip is unzipped into a temp folder. The installer run (`Flare-win-Setup.exe --silent`) happens in CI
  only (Task 37), on a clean runner.
- The diagnostics log never holds typed text, clipboard, audio, screen text, title text or conversation. A test
  writes a marker string through every path that takes text and searches the files (Task 35).
- A new dependency adds its line to `README.md`'s dependency list and its entry to `THIRD-PARTY-NOTICES.md`
  (`cargo about generate about.hbs`) in the same PR; `cargo deny check` passes. A new network request changes
  `PRIVACY.md` in the same PR (rule 113; Task 27's scan).
- **Main never waits on the disk or a process** (rule 34): the registry calls, the log writer, the update
  check and the download run on worker threads; the UI thread only posts and receives. Every blocking call in
  `flare`, `flare-win`, `flare-diag` or `flare-update` carries `// sync-ok: <reason>` on the same line (M2's scan
  test, extended to `flare-update` in Task 35). The two allowed synchronous writes: the log's quit flush and
  the panic hook's flush.
- CI on every PR: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo nextest
  run --workspace`, `cargo deny check`. Tests never touch the real registry outside a throwaway
  `HKCU\Software\FlareTest\<uuid>` subtree (unit tests, `SandboxRoot`) or `HKCU\Software\FlareE2E\<uuid>` subtree
  (the e2e `Sandbox`) that the test removes, never the network, never the real profile. The one place real
  `HKCU\Software\Classes` keys are written and removed is Task 37's Layer B, on a throwaway CI runner.
- Builders: Sonnet where marked, otherwise Haiku. Reviews: Opus. Never Fable.

## Review Focus

- **Install only what was offered** (Tasks 8, 9, 10, 11, 30): the UI sends a token, never a path or a version;
  the engine installs `offer.token` or nothing; a mock offer never downloads; `VelopackApp` auto-apply on
  startup is OFF (`set_auto_apply_on_startup(false)`), so a package lying in the packages folder is never
  applied by a later launch; cancel and every failure delete the package; the feed's `download` and `apply`
  take the OFFERED version and refuse when the stored check result is any other version; no check runs while
  an install runs; a cancelled download that is still finishing in the background makes the next `download`
  answer busy. Opus reads `engine.rs` and `velopack_feed.rs` end to end.
- **No network without the feature** (Tasks 10, 11, 35): search for `GithubSource`, `HttpSource`, `ureq`,
  `check_for_updates`, `download_updates` outside `velopack_feed.rs`; the constructor of the real source in that
  file is `#[cfg(feature = "live-updates")]`; a default build has no `Live` mode (`mode_for` returns `Off`).
- **The registry is touched only by the packaged app** (Tasks 14 to 16, 32): `allowed = packaged && !e2e` on
  every write including the Settings toggle; the write counter; the sandbox root under `--e2e`; a test reads
  the real keys before and after the whole e2e and compares.
- **A logger never throws and never blocks** (Tasks 18, 19, 31): a poisoned lock, a full disk, a held file, a
  read-only folder, a panic in a worker; the UI thread's `record` is a channel send; the quit flush is the one
  synchronous write.
- **The watchdog is safe** (Tasks 20, 22): it never holds a lock the UI thread can hold, it never suspends the
  UI thread unless Task 22's sampler proved itself against a thread that holds the heap lock, and a hung window
  is reported once.
- **Side by side** (Tasks 36, 37): different app id, install folder, uninstall key, shortcut name, verb key,
  verb label, single-instance mutex and pipe, profile, plugin name, hook signal, tab-id variable, AUMID, log
  folder, dictation folder; uninstalling Flare leaves every Prism Terminal value as it was.
- **Display scaling** (Tasks 12, 33, 40, 41): look at the eight-scale screenshots of the chip and the window:
  the chip edge is one device-pixel column, the track fill ends on a device pixel, the window box is centred
  to the pixel, the notice hairline is one device pixel, the 11 px arrow icon is centred in its 11 px box.

- `VelopackApp::build()` then `.run()` **must be the first thing `main` does**; "in some circumstances it may
  terminate/restart the process". (Re-checked 2026-10-17 by the plan review against the published crate source
  `velopack-1.2.161.crate`, `src/app.rs`, `src/manager.rs`, `src/locator.rs`, `src/sources/*.rs`, `src/download.rs`;
  the corrections below are from that source.) Builder methods (source `src/lib-rust/src/app.rs`): `set_args(Vec<String>)`,
  `set_auto_apply_on_startup(bool)` (**ON by default**: a downloaded newer package in the packages folder is
  applied at the next start, the app quitting), `set_app_user_model_id(&str)` (default: the manifest's
  `shortcutAumid`, else `velopack.{AppId}`), `set_locator(VelopackLocatorConfig)`, `on_first_run(FnOnce(Version))`
  (env `VELOPACK_FIRSTRUN`), `on_restarted(FnOnce(Version))` (env `VELOPACK_RESTART`), and the Windows-only
  fast callbacks `on_after_install_fast_callback` (30 s), `on_after_update_fast_callback` (15 s),
  `on_before_update_fast_callback` (15 s), `on_before_uninstall_fast_callback` (30 s): the process runs the
  callback and **exits**; no UI may be shown; a callback that overruns is killed. They are driven by the
  command-line arguments `--veloapp-install <ver>`, `--veloapp-updated <ver>`, `--veloapp-obsolete <ver>`,
  `--veloapp-uninstall <ver>` (docs "App Hooks"). **The hook arguments are handled FIRST, before any manager or
  locator** (`args[0]` is the hook flag, `args[1]` a semver; the hook runs, then `exit(0)` unless the variable

  `UpdateManager` over `NoneSource`; **on a dev build (not installed) that fails, is logged and `run()` returns**,
  so it is safe to call everywhere. `set_app_user_model_id` is applied only when that manager loads (an installed
  app), which is why Flare also sets the AUMID itself (Task 32). When the manager loads, `run()` deletes every
  local full package whose version is neither the running one nor a newer pending one; with auto-apply off a
  newer package is KEPT on disk (not applied), so Flare's own discard is what removes it. The `velopack::bundle`
  module (the `Manifest` type in `UpdateSource::get_release_feed`) is private without the crate feature
  `public-utils`: **Flare never implements `UpdateSource` itself**; it only constructs the crate's sources.

## Decisions taken by the planner (not the owner)

**D1. The updater switch is a compile-time cargo feature, `live-updates`, off by default.** Why a feature and
not a settings switch: (a) `PRIVACY.md` must be true of the binary ("one automatic request, off until the repo
is public"); a setting can be flipped by a damaged settings file or by the import from Prism Terminal, a missing
feature cannot; (b) a private repo's release assets answer an anonymous client with 404, so a live updater in
the private phase could only fail, and shipping a token in the app is never acceptable; (c) the flip is one
reviewed line (`default = ["live-updates"]` in `flare-update` and `flare`), a `PRIVACY.md` edit and a release,
which is the owner's explicit act on the day the repo goes public; (d) every behaviour is still tested every
day, because the engine, the feeds, the gate, the flow and the UI always compile: the feature gates ONLY the
constructor of the real GitHub source and the start of the checking thread. The release workflow builds with the
feature when the repo variable `FLARE_LIVE_UPDATES` equals `on`, so the owner's switch is also one variable.
There is no per-user toggle (Prism Terminal has none).

**D2. The offer carries an opaque token, not a URL.** Velopack decides the package; Flare never sees a download
URL. `Offer { version, notes, mock, token: u64 }` with a fresh token per offer; `Gate::install(Some(token))` runs
only when `token == current offer's token`. This is the native meaning of "install only what main offered"
(rule 101): the UI cannot name a package at all. Below the token, the version is the binding: the engine hands the
feed `offer.version`, and `Feed::download`/`Feed::apply` refuse (`Failed("not offered")`) when the feed's stored
check result is a different version, so a check that ran between the offer and the press can never swap the
package. The engine never runs a check while an install runs, and a re-check that finds the version already on
offer keeps that offer and its token (no new offer, no event).

**D3. Registry through the API, not `reg.exe`.** `flare-win::registry` calls `RegCreateKeyExW` and friends. No
process is spawned, so the PT rules "argument vectors only", "10 s timeout" and "run by full path" are met by
construction, and the "(Default) is translated" problem does not exist (values are read by type with
`RegGetValueW`, `RRF_RT_REG_SZ`). The PT test `readLabel` has its REG_SZ parser ported as `read_label_from_reg_output`
anyway (the pure function stays, used by nothing at run time, because the PT tests pin its behaviour and the
owner asked for parity of the tests; it carries a doc line saying so). [If the owner prefers dropping it, delete it
and its four tests in review.]

**D4. The verb points at `<install root>\current\Flare.exe`**, computed by `packaged::verb_exe`: the running exe
when it sits in a folder named `current` whose parent holds `Update.exe`. `current` keeps its name across updates
(only its contents change), so the verb survives an update without a rewrite; `Icon` is `<exe>,0` of the same file
(the embedded icon, Task 26). `pointsAt` compares case-insensitively with this path. An unpackaged build has no
verb exe: `verb_exe` is `None` and every write is refused.

**D5. `allowed = packaged && !e2e`** on every verb write, the Settings toggle included, and `writes()` counts the
attempts (PT `verbSwitch`). Under `--e2e` with `FLARE_E2E_VERB_ROOT=<subkey>` the SAME code writes under
`HKCU\<subkey>\Classes` instead of `HKCU\Software\Classes`, so the side-by-side scenario exercises the real write
path against a throwaway root; the real keys are read before and after the whole e2e and must be equal (Task 37).

**D6. Cancel is cooperative.** `download_updates` has no cancellation parameter. The install run owns a
`CancelToken` (`Arc<AtomicBool>`); the progress channel is read by the run's own thread; a cancel sets the flag, the
run stops waiting, deletes the package file(s) the download wrote under the Velopack packages folder as soon as the
worker returns, answers `false` and never calls apply. The bytes already in flight finish in the background and are
deleted; nothing is applied; `set_auto_apply_on_startup(false)` guarantees a leftover is never applied by a later
start. Observable behaviour equals PT's: cancel wins even after the last byte, leaves nothing, answers false.
While the abandoned download thread still runs, the feed is BUSY: a new `download` answers `Failed("busy")` at once
(so the joiner's discard can never delete a file a second download is writing; Velopack's own lock file would
refuse it too). The busy flag clears after the joiner has discarded.

**D7. The notes come from the feed.** `vpk pack --releaseNotes <file>` stores the markdown in the package, the feed
carries it as `NotesMarkdown`, the offer's `notes` is that string, cut to 20,000 UTF-16 units and parsed by the
ported parser (never rendered). The release workflow produces the file with GitHub's generate-notes API, so the
text has exactly the shape PT's parser was written for.

**D8. vpk flags (all in `tools/release/pack.ps1`):** `--packId Flare --packTitle Flare --packAuthors Max
--mainExe Flare.exe --icon build\icon.ico --shortcuts StartMenuRoot --aumid com.flare.terminal --runtime win-x64
--channel win --delta BestSpeed --releaseNotes <file> --packDir <staging> --outputDir <Releases>`. No `Desktop`
shortcut (PT: no desktop shortcut), no splash image (O15: one-click), unsigned, x64 only (`--runtime win-x64`).
The staging folder holds `Flare.exe`, `conpty.dll`, `OpenConsole.exe`, the Claude plugin folder as
`claude-plugin\` beside the exe (M6 D8: `flare_agent::plugin::plugin_dir()` looks for `<exe dir>\claude-plugin`;
the source is `crates\flare-agent\claude-plugin`; the plugin's own NAME inside it is `flare-status`), the
dictation engine files M8 ships **[seam: the folder and the name the app looks for beside the exe are M8's,
read them from M8's committed `build.rs` copy list and `flare-dictation` source]**, `LICENSE`,
`THIRD-PARTY-NOTICES.md` (parity: "Shipped beside the app").

**D9. `packaged` means "installed by Velopack"**: the exe's folder is named `current`, the parent folder holds
`Update.exe`, and the parent folder does NOT hold the file `.portable` (Velopack's own portable marker, read by
`create_config_from_root_dir`). A `cargo run` build, a copied exe and an unzipped portable copy are not packaged,
so a portable copy leaves no trace in the registry and never checks for updates. `is_packaged` is a pure
function over paths, tested with temp folders; Task 29 confirms on the real portable zip that `.portable` is
there.

**D10. Hooks.** `VelopackApp::build().set_auto_apply_on_startup(false)` plus one real hook,
`on_before_uninstall_fast_callback`, which removes both verb keys (parity with `customUnInstall`; the key list is
read from `verb_keys()`, never retyped). `on_after_install_fast_callback` and `on_after_update_fast_callback` are
registered as no-ops that return at once: the verb is reconciled at the next launch exactly like PT's, which keeps
every hook tiny and far under the 15 and 30 second limits. `on_first_run` cannot write to the log (the log does
not exist yet inside `run()`): it stores the version in a `static FIRST_RUN: OnceLock<String>` and Task 31's
start writes the crumb `first-run` from it.
`run()` is the first statement of `main`, before argument parsing, before the single-instance lock and before any
thread. A hook run exits the process, so nothing after `run()` executes during a hook. **Under `--e2e` the
uninstall hook removes keys ONLY under a valid `FLARE_E2E_VERB_ROOT` (under `Software\FlareE2E\`) and does nothing
otherwise; it never falls back to the real `Software\Classes`** (a test run on the owner's PC must not be able to
delete the verb of a Flare the owner installed by hand).

**D11. Preview and mode** (`mode_for`): `Preview` when `--preview-update` is present (exact match; also in the
installed app and under `--e2e`) or when the build is not packaged and not `--e2e`; else `Live` when packaged,
not `--e2e`, and `cfg!(feature = "live-updates")`; else `Off`. Under `--e2e` a real-shaped offer `99.0.0` appears
when `FLARE_E2E_UPDATE_OFFER` is set, served by a `RefusingFeed` whose download fails before it starts.

**D12. Diagnostics kinds for a native app (O16).** `src` is `"app"` on every line (one process, no page).
Mapping: `main-lag` stays (the UI thread's 50 ms heartbeat late by 100 ms or more, with the work items running or
ended inside the lag as `inflight`); `fs-slow` stays (a worker thread stats the profile folder every 5 s, 500 ms);
`mem-high` stays (`proc` is `app`, `gpu` or `children`); `page-stall` becomes `frame-slow` (a frame whose
update-and-paint ran 200 ms or more, with the last 5 crumbs); `page-stack` becomes `ui-stack` (the UI thread
missed 2 s of heartbeats; its sampled stack when Task 22's sampler is on, else the work items running);
`ipc-slow` and `ipc-error` become `work-slow` and `work-error` (a timed UI-thread work item over 500 ms, a
synchronous one over 100 ms; items that wait on the user, `WorkClass::Waits`, are never slow); `page-error` and
`main-error` become `panic` (the hook; also `render-error`); `page-rejection` and `main-rejection` have no Rust
equivalent and are dropped (documented); `gone` stays (a shell or the GPU device ended); `unresponsive` and
`responsive` stay (`IsHungAppWindow`); `crumb`, `mark`, `verbose`, `logger-error`, `logger-dropped`, `session`,
`quit`, `session-end`, the `agent-*` kinds and any `*-slow` stay as they are. The reader knows the new names.
**`mark` carries no note in Flare**: M7's `DiagControlApi::mark(&self)` takes no text (PT's optional typed note is
not ported), so the `mark` line is `{}` and the log holds no typed text at all, with no exception.

**D13. The reader is a cargo alias**: `.cargo/config.toml` `[alias] diag = "run -q -p flare-diag --bin diag --"`, so
`cargo diag --since 10m`. Its `--app` flag is replaced by `--dir` (default `%APPDATA%\Flare\logs`) and `--profile
<folder>` (that folder's `logs`).

**D14. One-click setup, no licence page.** O15 decided one-click; Velopack's Setup has no licence screen (the MSI
does, unused). Prism's own licence-screen rule is Prism's. Question Q1 asks the owner; the default stands.

**D15. Release identity.** Tag `v<version>` where `<version>` is `[workspace.package] version` of the root

parity line's "a same-version push replaces that release's installer" is NOT ported: PT v0.55.6's own

## Appendix D: the release workflow and the two scripts (Task 28 copies these; the tests in `release_files.rs` read them)

`.github/workflows/release.yml`:

```yaml
# Every merge to main is a release when it carries a new version (D15).
# Gates first, then vpk pack, then the side-by-side run against Prism Terminal on this clean runner,
# then the release v<version> on this (private) repository. A version that is already released
# publishes nothing and says so, without failing. The updater inside the app is switched off until
# the repository is public (docs/updater-flip.md); FLARE_LIVE_UPDATES=on builds it in.
name: release

on:
  push:
    branches: [main]

concurrency:
  group: release-main
  cancel-in-progress: false

env:
  CARGO_TERM_COLOR: always
  VPK_VERSION: 1.2.161

jobs:
  release:
    runs-on: windows-latest
    timeout-minutes: 60
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4

      - name: Is this version already released?
        id: ver
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          $toml = Get-Content Cargo.toml -Raw
          if ($toml -notmatch '(?ms)\[workspace\.package\].*?^version\s*=\s*"([^"]+)"') { throw "no workspace version in Cargo.toml" }
          $v = $Matches[1]
          "version=$v" >> $env:GITHUB_OUTPUT
          gh release view "v$v" *> $null
          if ($LASTEXITCODE -eq 0) {
            "fresh=false" >> $env:GITHUB_OUTPUT
            Write-Host "::notice::v$v is already released. Nothing to publish (bump the version in Cargo.toml in a PR to release)."
          } else {
            "fresh=true" >> $env:GITHUB_OUTPUT
          }
          $global:LASTEXITCODE = 0

      - name: Toolchain
        if: steps.ver.outputs.fresh == 'true'
        run: rustup toolchain install

      - uses: Swatinem/rust-cache@v2
        if: steps.ver.outputs.fresh == 'true'

      - uses: taiki-e/install-action@v2
        if: steps.ver.outputs.fresh == 'true'
        with:
          tool: cargo-nextest,cargo-deny

      - name: No em-dashes
        if: steps.ver.outputs.fresh == 'true'
        shell: bash
        run: |
          dash="$(printf '\342\200\224')"
          if git grep -n "$dash" -- . ':!Cargo.lock'; then
            echo "Em-dash found (owner rule: use en-dashes, commas or rephrase)"; exit 1
          fi

      - name: Format
        if: steps.ver.outputs.fresh == 'true'
        run: cargo fmt --check

      - name: Clippy
        if: steps.ver.outputs.fresh == 'true'
        run: cargo clippy --workspace --all-targets -- -D warnings

      - name: Tests
        if: steps.ver.outputs.fresh == 'true'
        run: cargo nextest run --workspace --no-tests=pass

      - name: Deny
        if: steps.ver.outputs.fresh == 'true'
        run: cargo deny check

      - uses: actions/setup-dotnet@v4
        if: steps.ver.outputs.fresh == 'true'
        with:
          dotnet-version: 8.0.x

      - name: vpk
        if: steps.ver.outputs.fresh == 'true'
        run: dotnet tool install -g vpk --version $env:VPK_VERSION

      - name: Build
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          # The updater stays OFF while the repository is private (owner, 2026-10-17; docs/updater-flip.md).
          $vis = gh repo view "${{ github.repository }}" --json visibility --jq .visibility
          if ($LASTEXITCODE -ne 0 -or [string]::IsNullOrWhiteSpace($vis)) { throw "could not read the repository visibility" }
          $flipped = Select-String -Path crates/flare/Cargo.toml, crates/flare-update/Cargo.toml -Pattern '^\s*default\s*=\s*\[[^\]]*live-updates' -Quiet
          $features = @()
          if ('${{ vars.FLARE_LIVE_UPDATES }}' -eq 'on') { $features = @('--features', 'live-updates') }
          if (($features.Count -gt 0 -or $flipped) -and $vis -ne 'PUBLIC') {
            throw "the updater is switched on but the repository is $vis; it stays off until the repository is public"
          }
          cargo build --release -p flare @features
          if ($LASTEXITCODE -ne 0) { throw "release build failed" }

      - name: Release notes
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
        run: ./tools/release/notes.ps1 -Tag "v${{ steps.ver.outputs.version }}" -Out notes.md

      - name: Previous release, so the pack can make deltas
        if: steps.ver.outputs.fresh == 'true'
        continue-on-error: true
        run: vpk download github --repoUrl "https://github.com/${{ github.repository }}" --token "${{ github.token }}" --outputDir Releases

      - name: Pack
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        run: ./tools/release/pack.ps1 -Version "${{ steps.ver.outputs.version }}" -Exe target/release/flare.exe -Notes notes.md -Out Releases

      - name: Verify the pack
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        run: ./tools/release/verify-pack.ps1 -Out Releases -Version "${{ steps.ver.outputs.version }}"

      - name: Flare beside Prism Terminal, installed for real on this clean runner
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
          FLARE_E2E_INSTALL: '1'
          FLARE_EXE: target/release/flare.exe
          FLARE_RELEASES: Releases
        run: cargo test -p flare-e2e --test side_by_side -- --include-ignored

      - name: Keep the symbols
        if: steps.ver.outputs.fresh == 'true'
        uses: actions/upload-artifact@v4
        with:
          name: flare-symbols-${{ steps.ver.outputs.version }}
          path: target/release/flare.pdb
          retention-days: 30

      - name: Publish
        if: steps.ver.outputs.fresh == 'true'
        shell: pwsh
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          $v = "${{ steps.ver.outputs.version }}"
          # Not over a newer workflow (PT, 2026-09-28): the token cannot tag a commit whose workflows differ from main's.
          git fetch -q --depth=1 origin main
          git diff --quiet "${{ github.sha }}" FETCH_HEAD -- .github/workflows
          if ($LASTEXITCODE -ne 0) {
            "::notice::main has moved past ${{ github.sha }} with changed workflows; the next release run publishes v$v."
            exit 0
          }
          vpk upload github --repoUrl "https://github.com/${{ github.repository }}" --token "${{ github.token }}" --publish --releaseName "Flare $v" --tag "v$v" --targetCommitish "${{ github.sha }}" --outputDir Releases
          if ($LASTEXITCODE -ne 0) { throw "Release publication failed" }
          $assets = gh release view "v$v" --json assets --jq '.assets[].name'
          if (-not ($assets -contains 'releases.win.json')) { throw "the release has no releases.win.json" }
```

`tools/release/pack.ps1`:

```powershell
# Builds the staging folder and runs vpk pack (decision D8). Fails when anything the app ships beside it is missing.
param(
  [Parameter(Mandatory)][string]$Version,
  [Parameter(Mandatory)][string]$Exe,
  [Parameter(Mandatory)][string]$Notes,
  [Parameter(Mandatory)][string]$Out,
  [string]$Stage = (Join-Path $env:TEMP 'flare-stage')
)
$ErrorActionPreference = 'Stop'
$root = (Resolve-Path (Join-Path $PSScriptRoot '..\..')).Path
function Need([string]$p) { if (-not (Test-Path -LiteralPath $p)) { throw "missing: $p" }; return $p }
if (Test-Path -LiteralPath $Stage) { Remove-Item -Recurse -Force -LiteralPath $Stage }
New-Item -ItemType Directory -Force -Path $Stage | Out-Null
Copy-Item -LiteralPath (Need $Exe) -Destination (Join-Path $Stage 'Flare.exe')
foreach ($f in 'conpty.dll', 'OpenConsole.exe') {
  Copy-Item -LiteralPath (Need (Join-Path $root "crates\flare-term\bundled\x64\$f")) -Destination $Stage
}
# The Claude plugin: M6 D8, the app looks for <exe dir>\claude-plugin and ships it only when hooks\hooks.json exists.
$plugin = Need (Join-Path $root 'crates\flare-agent\claude-plugin')
Need (Join-Path $plugin 'hooks\hooks.json') | Out-Null
Copy-Item -Recurse -LiteralPath $plugin -Destination (Join-Path $Stage 'claude-plugin')
# The dictation engine: [seam] M8's folder and the name the app looks for beside the exe (from M8's build.rs copy list).
$engine = Need (Join-Path $root 'crates\flare-dictation\bin')
Copy-Item -Recurse -LiteralPath $engine -Destination (Join-Path $Stage 'bin')
foreach ($f in 'LICENSE', 'THIRD-PARTY-NOTICES.md') { Copy-Item -LiteralPath (Need (Join-Path $root $f)) -Destination $Stage }
vpk pack --packId Flare --packTitle Flare --packAuthors Max --packVersion $Version --packDir $Stage --mainExe Flare.exe --icon (Join-Path $root 'build\icon.ico') --shortcuts StartMenuRoot --aumid com.flare.terminal --runtime win-x64 --channel win --delta BestSpeed --releaseNotes $Notes --outputDir $Out
exit $LASTEXITCODE
```

`tools/release/notes.ps1`:

```powershell
# GitHub's generated release notes for a tag, or the one sentence the parser treats as "no notes".
param([Parameter(Mandatory)][string]$Tag, [Parameter(Mandatory)][string]$Out)
$ErrorActionPreference = 'Continue'
$body = $null
try {
  $body = gh api -X POST "repos/$env:GITHUB_REPOSITORY/releases/generate-notes" -f "tag_name=$Tag" --jq .body
  if ($LASTEXITCODE -ne 0) { $body = $null }
} catch { $body = $null }
if ([string]::IsNullOrWhiteSpace($body)) { $body = 'No notes were published with this release.' }
[System.IO.File]::WriteAllText($Out, $body, (New-Object System.Text.UTF8Encoding($false)))
Get-Content -LiteralPath $Out -TotalCount 5
exit 0
```

**Goal:** Flare knows what the agent in a tab is doing and says so, and brings a conversation back.
The indicator is the agent's own word: the terminal title first, Claude Code's hook signal above it
(`OSC 777;flare-agent` from the bundled `flare-status` plugin), output scoring only as the fallback for
a session with no title and no hook, and a hooked session is never scored from its output. A spinner
after a question is Working; a Question holds while its box is on the screen; a Stop with the spinner
up waits for the next title. The agent poll (a native process snapshot, backed off 2.5 to 20 s) says
when an agent is in a tab and which one. The marks (working, question, finished, failed; Ring or Bar;
the rainbow finish) are drawn on the strip, the sidebar and the +N list at every display scaling from
100 to 300 percent, and counted in the taskbar overlay. The agent clock, the tab's agent icon, the
"Failed: kind" tooltip, Keep-agents-open, agent hotkeys, the question widget read for Sonara, the
diagnostics kinds, the Claude plugin and how a shell is handed it, agent resume on restore (the ONLY
command Flare writes into a shell: the shell's startup command, the id validated and carried in
`FLARE_RESUME_ID`, one command line per shell kind, no `-EncodedCommand`), the launch skeleton and
Codex detection are all here. Every Prism Terminal v0.55.6 unit test that `docs/test-port.md` maps to
these areas is ported as a Rust test (ledger in Appendix A).

**Architecture:** Everything with a rule is a UI-free module of `flare-agent`, with time passed in and
every outside thing behind a trait, so the measured timelines replay without a window.

## Global Constraints

Copied from the roadmap and M2 to M5; every task obeys them.

- Windows 10 1809+ / 11, x64 only. Proprietary licence. **No em-dashes** anywhere (code comments, docs, test
  strings, UI copy, the plugin files); CI greps for them.
- Flare's own names only: plugin `flare-status`, signal `OSC 777;flare-agent;...`, tab id variable
  `FLARE_TAB_ID`, resume variable `FLARE_RESUME_ID`, setting keys `flare.*` (decision O10), e2e seams
  `FLARE_E2E_*`. Never a Prism name in an identifier, path, key, header or string (docs may name Prism
  Terminal as the source). **Flare must not accept `prism-agent`** and must never load or drop a
  `prism-terminal-status` plugin differently from any other user plugin (rule 109, 123).
- **Every display scaling works** (roadmap, owner 2026-10-17: "it has to work on all sorts of different DPI
  scalings, like 150 or 200 percent"): 100, 125, 150, 175, 200, 225, 250 and 300 percent, both renderers,
  moving between monitors. For this milestone: every mark's thickness, edge and gap is a whole number of
  device pixels (`Px.snap`, the M3 helper), a 3 px line is `max(1, round(3 * scale))` device pixels, a ring
  is centred in its slot to the device pixel, and every mark test runs at the eight scales (Tasks 24, 25, 29);
  the screenshots are taken at all eight (Task 34).
- The indicator is the agent's own word (rule 57): title first, hook above it, scoring only as fallback.
  A hooked session is never scored from output (rule 59). A spinner after a question is Working, never from
  the answer key; a Stop with the spinner up waits for the next title; a Question holds while its box is on
  screen (rule 60). Finished and Failed are news, Question is state (rule 61).
- **The only command ever written into a shell is the agent resume** (rule 2, with the cd line of decision O1
  kept as a guarded, uncalled function: Prism Terminal's host answers `mayCd: false`, so nothing calls it).
  The resume is the startup command built from argv Flare owns, the id validated by `valid_resume` in THREE
  places (the lookup `ClaudeSessionLookup::sessions` drops every id that fails it, `TabHost::spawn`,
  `SessionManager::spawn`), carried in `FLARE_RESUME_ID` and cleared in the startup line before the agent
  starts (M2's `with_resume`, unchanged). Every shell of a kind has the same command line (rule 3). No
  `-EncodedCommand`, no string built from a session id. This milestone adds no pty write path. **Why the
  validation is load-bearing:** cmd's line `set FLARE_RESUME_ID=& claude --resume %FLARE_RESUME_ID%` expands
  the variable BEFORE it parses the line, so a value holding `&` or `|` would run as a command; only hex and
  `-` (or the exact marker `codex:last`) may ever reach the environment.
- A resume is not new work (rule 38): during the restore a tab accepts idle titles only until its own turn
  starts; no Finished, Question or Failed comes from a resume. The clear before the agent paints goes to the
  grid only, never the shell (rule 39).
- The diagnostics kinds hold no typed text, screen text, title text or conversation (rule 110): states, rule
  names, tab ids, the folder and counts only. A test writes a marker string through every path and proves it
  never reaches the sink.
- **UI thread never waits (rule 34).** The process snapshot, the Claude session lookup, the Sonara post, the
  hook-script spawn in tests and every `std::fs` read run on worker threads; any blocking call in non-test
  code in `flare-agent`, `flare-diag`, `flare-win` or `flare` carries `// sync-ok: <reason>` on the same line
  (M2's scan tests enforce it; Task 35 extends them to `flare-agent`).
- New dependency = a reason line in `README.md`'s dependency list and a `THIRD-PARTY-NOTICES.md` entry in the
  same PR (Task 35); `cargo deny check` passes. Pin with `=`. Every `pub fn new() -> Self` with no arguments
  also gets `impl Default`.
- CI gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo nextest run --workspace`, `cargo deny check`.
- Nothing in tests may open a visible window, take the foreground, touch the real clipboard, the real
  `%APPDATA%\Flare`, the owner's `~/.claude` or the real taskbar. Tests that need a folder use `tempfile`; tests
  that start a process reap it. The one test that spawns `cmd.exe` (Task 3) runs a script of its own in a temp
  folder. UI tests use the headless software platform only.
- Builders: Haiku by default, Sonnet where marked. Reviews: Opus. Never Fable.
- The PR reports test counts, the screenshots (Task 34), the cold-restore timing of a Claude tab (Task 32) and
  the Opus findings.

## Review Focus

- **Hooked is hooked** (Tasks 5, 17, 18, 31): no code path scores a hooked session's output; the screen of a
  hooked session is read only inside `apply_hook` when `screen_decides` says so, plus the answer-key reads, the
  background re-read and the question widget watch. Opus greps `indicator.rs` for every `tail(` call.
- **The measured timelines** (Task 5): A, B, C, D, E, G2, C3 replay to the same shown states as Prism Terminal
  at every 100 ms; no edit of a fixture; the replay is a faithful port of the TS `replay`, not a re-derivation.
- **Resume safety** (Tasks 10, 23, 30, 32): an id that is not a session id never reaches a command line; the
  restored Claude tab resumes the newest INTERACTIVE session of its own folder only; a plain shell tab never
  resumes; bash and WSL get no resume; a cold restored Claude tab starts as fast as a repeat (M2's constant
  command line), measured on the release build.
- **The plugin** (Tasks 3, 30): hooks.json is exec form, 25 entries, timeout 5, `cmd.exe /d /c call
  "${CLAUDE_PLUGIN_ROOT}/hook.cmd" ...`; hook.cmd is CRLF, a static echo, reads no stdin; a Flare started from
  another Flare's tab drops the inherited `flare-status` folder and adds its own; `claude -p` never lights a
  tab (it never writes the sequence); another OSC 777 user is left alone.
- **Motion costs nothing at rest** (Tasks 14, 29): with no mark moving the mark timer is stopped (zero
  wakeups); a minimised window moves no mark; Windows' "animation effects" off stills every mark. Opus reads
  the process's CPU time over 10 s.
- **Display scaling** (Tasks 24, 25, 34): look at the eight-scale screenshots mark by mark: the 3 px line and
  its rounded run bar crisp and the same weight on every tab, the ring centred in its slot, the check and cross
  not blurred, Clawd's pixels square, the +N dots round, the taskbar disc sharp at 36 px.
- **Privacy** (Tasks 15, 28): the diagnostics lines hold no title text or screen text; Sonara receives the
  question text only on 127.0.0.1 and only when `runtime.json` exists.

## Decisions taken by the planner (not the owner)

D1. **`flare-agent` stays free of Win32 and UI types.** The process snapshot, the taskbar overlay and the
   animation switch are `flare-win`'s; `flare-agent` takes them through traits and closures. `flare-term`
   depends on `flare-agent` (the reveal rules, `valid_resume`, the `Screen` and `RowSource` traits' users);
   `flare-agent` never depends on `flare-term`, `flare-tabs` or `flare-win` (no cycle: `flare-tabs` already
   depends on `flare-agent`).
D2. **The indicator is one struct with injected time.** `Indicator::handle(now_ms, event, &dyn Screen)` and
   `Indicator::tick(now_ms, &dyn Screen)`; it owns its deadlines (`next_due()`), the glue wakes at the next
   one. PT's React effects (the finished-while-away effect) are `reconcile()`, called at the end of every
   entry point. This is what lets the seven measured timelines replay without a clock or a window.
D3. **The poll runs on its own worker thread, synchronously.** `AgentPoll::look(as_forced)` blocks on the
   query; the worker loops `recv_timeout(2.5 s)` over a command channel (`Look`, `Again(id)`, `Soon`, `Stop`).
   Prism Terminal's `agentBusy` flag disappears (a look cannot overlap itself); an ask that arrives while a look
   runs waits in a shared set (`PollHandle`) and is kept for the next look, which is the same behaviour.
D4. **The process query is native** (`flare-win::procs`): ToolHelp32 for pid and parent pid, then
   `NtQueryInformationProcess(ProcessCommandLineInformation)` for the command lines of the DESCENDANTS of the
   live shells only, filtered by the same broad `claude|codex|aider|gemini` word test before the strict
   `AGENT_RE`. No PowerShell, no WMI. A process that cannot be opened (elevated) has an empty command line and is
   skipped; only a failed snapshot is a failed query. The compact "pid ppid command" text listing and its five
   tests are dropped (the rows are structs now); the tree walk tests are kept.
D5. **Mark motion is one clock, owned by Rust.** `ui/tabmark.slint` has `global MarkMotion` (spin angle,
   breathe opacity, run position, flow offset, the seven rainbow colours); `AppCtl` owns ONE `slint::Timer`
   (16 ms) that runs only while some mark moves AND the window is not minimised AND Windows' animation effects
   are on; otherwise the values are the "still" set and the timer is stopped. The pure math is
   `flare_agent::mark_motion` (Task 14), so every frame of every motion is a unit test. This is the native
   meaning of marks.css, `data-marks-paused` and `prefers-reduced-motion`.
D6. **Ring and Bar only.** `off`, `full`, the Powerline `prompt` tab style, the Full fill, the edge mark and
   the `overlay` do not exist in Flare (parity: "Flare has no Off and no Full"). The PT cells of `tabMark.test`
   and `TabMark.test` for them are dropped with a one-line note each in the ledger; the stored word `minimal`
   is Bar and anything else is Ring.
D7. **The resume reveal splice lives in `TermHandle`**, the object that owns the emulator and sees the raw
   chunks (PT put it next to xterm's `write`). The rules are `flare_agent::reveal` (pure). The skeleton itself
   is drawn by Slint over the grid area of the FRONT agent tab while `handle.resuming()` is true (every
   restoring tab shows the ring in its tab regardless).
D8. **The plugin ships in `crates/flare-agent/claude-plugin/`** and `crates/flare/build.rs` copies it to
   `<profile>/claude-plugin` next to the exe (the same way it copies ConPTY); the installer (M9) ships the folder
   beside the exe. `flare_agent::plugin::plugin_dir()` resolves: `FLARE_CLAUDE_PLUGIN_DIR` (when set and
   non-empty it is the only candidate; the e2e seam), `<exe dir>\claude-plugin`, and in debug or from a `deps`
   folder `CARGO_MANIFEST_DIR\claude-plugin`. It is shipped only if `hooks\hooks.json` exists in it. The folder
   is handed to a shell as `CLAUDE_CODE_PLUGIN_DIRS` by M2's `pty_env`, exactly as PT's `ptyEnv` (user folders
   kept in order, ours appended, an inherited copy of ours dropped, the variable removed if empty, key spelling
   kept, a warm shell adopted only with the same plugin key). "Exact status from Claude Code" is the setting
   `flare.term.agentHooks`, on by default; only a NEW shell sees a change.
D9. **The question widget is watched for every tab** (as PT) after output settles (150 ms) and posted to Sonara
   on a worker thread; with no `runtime.json` nothing is sent and nothing fails. The post is a hand-written

`look` is the TS body in the same order. No pids -> return. `start_at = now()`. If `fails > 0 && start_at < fail_next` return (a failing query backs off for everyone, forced looks too). `force = as_forced && last_start.map_or(true, |l| start_at - l >= AGENT_FORCE_GAP)`.
`ticks = deps.ticks()`; `quiet = Some(ticks) == seen_ticks`; `asked = handle.snapshot()` (a COPY, not yet cleared); `known = every pid has an agent_state entry AND is not in asked`. `if quiet && known && !force` return. `now = deps.now()`; `if known && now < next && !force` return.
Then `last_start = Some(start_at)`; `asking = handle.take()` (clear the shared set and keep the copy); `rows = deps.query(&pids)`; an empty or None answer: `handle.put_back(asking)`, `fails += 1`, `fail_next = now() + min(AGENT_FAIL_MAX, AGENT_POLL_MIN.saturating_mul(1u64 << fails.min(16)))`, say `failing` exactly when `fails == 3`, return WITHOUT touching `seen_ticks`.
A good answer: `fails = 0`, `seen_ticks = Some(ticks)`; for each live `(id, pid)` (read `deps.pids()` again): `kind = tree_agent_kind(&rows, pid)`, `has = kind.is_some()`; if `agent_state.get(id) != Some(&has)` { set, `changed = true`, `send(id, has, kind)` } else if `asking` has id { `send(id, has, kind)` }; forget states of ids no longer alive; `every = if changed { AGENT_POLL_MIN } else { min(AGENT_POLL_MAX, every * 2) }`; `next = now() + every`.

# Flare Milestone 1: window, chrome and the grid on both renderers (detailed plan)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (run as a
> Workflow, one `agent()` per task). Steps use checkbox (`- [ ]`) syntax. Every task is TDD: write
> the failing test, run it and see it fail, implement, run it and see it pass, commit. Each task
> names its model: **Haiku** unless marked **Sonnet**. Opus only reviews (Task 19).

**Goal:** A frameless Slint window that looks like Prism Terminal's top row (mark, empty tab strip,
cog, minimize, maximize, close) over the default theme's ground, with a static terminal grid drawn
by `flare-render` either on the GPU (wgpu texture, glyph atlas, instanced quads) or in software
(CPU RGBA buffer), both fed by the same glyph rasteriser, filling the area under the bar, correct
from 100% to 225% DPI, re-rendering on resize, falling back to software when the GPU cannot start,
with frame time and memory measured and a headless `--screenshot` for visual checks.

**Architecture:** `crates/flare-render` is window-free: a `Grid` model, colour resolution, cell
metrics, a pure layout step that turns a grid into a `Scene` (rects, glyph draws, overlays), a
`GlyphSource` trait (cosmic-text + swash rasteriser in production, a fake in tests), a CPU
renderer that paints a `Scene` into RGBA, and a GPU renderer that paints the same `Scene` into a
`wgpu::Texture` through a shelf-packed glyph atlas. `crates/flare` owns Slint: it picks Slint's
renderer at start (`femtovg-wgpu` for GPU, `software` otherwise), receives Slint's own wgpu
device through `set_rendering_notifier`, and shows the grid as a `slint::Image` (an imported
`wgpu::Texture` on GPU, a `SharedPixelBuffer` on software). One Scene, two painters, one layout.

**Tech Stack (exact, verified 2026-10-17 on crates.io and by compiling and running a prototype on
this PC, see "Verified facts"):** Rust 1.99 MSVC, edition 2024; `slint =1.18.1`,
`slint-build =1.18.1`, `wgpu =30.0.1` (the version behind Slint's `unstable-wgpu-30`),

## Review Focus

- GPU unavailable (RDP, VM, `SLINT_WGPU_CPU` unset with only WARP): `select()` fails fast, Flare
  falls back to the software renderer, logs `renderer: software (fallback: <reason>)`, overlay
  shows it. Pinned by Task 15's config tests and the `--probe-backend` + `FLARE_FORCE_GPU_FAIL=1`
  binary test in `crates/flare/tests/headless.rs` (no window).
- Resize at 225% and while maximized: grid texture size equals the Image element's physical size
  exactly (`round(width / 1phx)`), no blur, no stale stretched frame beyond one, no busy redraw loop.
- Texture limits: Slint's default wgpu limits are `downlevel_webgl2_defaults` (2048 max texture).
  Flare must raise `device_required_limits` to `wgpu::Limits::default()` (8192) or a 4K window at
  225% fails. Pinned in Task 15.
- GPU vs CPU pixel parity (Task 11 test), colour glyphs (emoji) premultiplied handling.
- Memory: wgpu DX12 device creation on this PC costs about 120 MB working set and 350 to 430 ms
  (measured, see below). That is a risk to the performance bar (cold start < 300 ms, idle memory a
  third of PT). M1 reports it; it is an owner question if it holds (see "Questions for the owner").

## Verified facts (2026-10-17; prototype in `scratchpad\proto` and `scratchpad\proto2`)

- `slint 1.18.1` features: `unstable-wgpu-30` (wgpu `^30`), `renderer-femtovg-wgpu`,
  `renderer-software`, `backend-winit`. **`compat-1-18` must be enabled** when default features are
  off (compile_error otherwise). Software renderer with `std` includes `path` and `systemfonts`.
- `BackendSelector::new().backend_name("winit".into()).renderer_name("femtovg-wgpu".into())
  .require_wgpu_30(WGPUConfiguration::Automatic(settings)).select()` works. `select()` **fails
  before installing a platform** when no GPU-backed adapter exists (message mentions
  `SLINT_WGPU_CPU`), so a second `BackendSelector` with `.renderer_name("software".into())` can be
  tried. Explicit backend/renderer names win over `SLINT_BACKEND`.
- `WGPUSettings` is `#[non_exhaustive]`: build with `WGPUSettings::default()` then assign pub
  fields. Its default `device_required_limits` is `Limits::downlevel_webgl2_defaults()`.
- `GraphicsAPI::WGPU30 { instance, device, queue, .. }` arrives in `RenderingState::RenderingSetup`.
  `slint::Image::try_from(wgpu::Texture)` needs format `Rgba8Unorm` or `Rgba8UnormSrgb` and usage
  `TEXTURE_BINDING | RENDER_ATTACHMENT` (else `TextureImportError`). `set_rendering_notifier`
  returns `Err(SetRenderingNotifierError::Unsupported)` on the software renderer.
- If wgpu fails later, at window creation, Slint's winit backend silently retries another renderer;
  Flare detects that because `RenderingSetup` then carries no `WGPU30` api.
- Frameless window: `no-frame: true`; Slint's winit backend already gives resize borders to an
  undecorated resizable window. `WindowMoveArea { }` is a public 1.18 element that moves the window
  on press-and-drag; a plain click still reaches child `TouchArea`s.
- `changed <prop> => { }` callbacks work. `round(img.width / 1phx)` gives the exact physical size
  (without `round`, 800 px at 2.25 read as 799). `1px / 1phx` is the scale factor.
- Headless: `MinimalSoftwareWindow::new(RepaintBufferType::NewBuffer)` + a `Platform` whose
  `create_window_adapter` returns it, `dispatch_event(WindowEvent::ScaleFactorChanged{..})`,
  `set_size(PhysicalSize)`, `draw_if_needed(|r| { r.render(&mut [PremultipliedRgbaColor], stride); })`
  renders the whole UI with no OS window. Chrome screenshots at 1.0 and 2.25 were checked by eye.
- wgpu 30: `Instance::new(InstanceDescriptor { backends, ..InstanceDescriptor::new_without_display_handle() })`;
  `request_adapter(&RequestAdapterOptions { .., ..Default::default() })` returns `Result`
  (struct has a new field `apply_limit_buckets`, so always use `..Default::default()`);
  `request_device(&DeviceDescriptor { label, ..Default::default() })` returns `Result<(Device, Queue)>`;
  `PipelineLayoutDescriptor { label, bind_group_layouts: &[Some(&bgl)], immediate_size: 0 }`
  (layouts are `Option`); `RenderPipelineDescriptor` has `multiview_mask: None, cache: None`;
  `RenderPassDescriptor` has `multiview_mask: None`; `RenderPassColorAttachment` has
  `depth_slice: None`; `device.poll(wgpu::PollType::wait_indefinitely())` returns `Result`;
  `BufferSlice::get_mapped_range()` returns `Result<BufferView, _>`;
  copies use `TexelCopyTextureInfo`, `TexelCopyBufferInfo`, `TexelCopyBufferLayout`;
  `wgpu::COPY_BYTES_PER_ROW_ALIGNMENT == 256`.
- cosmic-text 0.19: `Buffer::new_empty(Metrics::new(px, line_px))`;
  `buffer.set_text(text, &attrs, Shaping::Advanced, None)` (no font_system argument);
  `buffer.shape_until_scroll(&mut font_system, false)`; `run.glyphs[i].physical((0.0, 0.0), 1.0)`
  gives `PhysicalGlyph { cache_key, x, y }`; `swash_cache.get_image(&mut fs, key) -> &Option<SwashImage>`
  with `placement { left, top, width, height }` and `content: SwashContent::{Mask, Color, SubpixelMask}`.
  `font_system.get_font(id, Weight::NORMAL).unwrap().metrics()` is skrifa `Metrics` in font units.
  Measured: Cascadia Mono `units_per_em 2048, ascent 1900, descent -480, leading 0`, advance
  `1200` units (17.138672 px at 29.25 px). `中` falls back to Microsoft YaHei UI (mask), `😀` to
  Segoe UI Emoji (**Color**, premultiplied: swash composites layers onto a transparent buffer).
  `─` has `left = -2`, width 21 at 29.25 px: box glyphs overhang the cell on purpose. FontSystem
  load: 62 ms, 1.5 MB.
- Measured on this PC (RTX 5090, release build): DX12 device creation 350 to 430 ms and about
  +120 MB working set, +200 to 370 MB private bytes.
- Memory query: `windows_sys::Win32::System::ProcessStatus::{GetProcessMemoryInfo,
  PROCESS_MEMORY_COUNTERS_EX}` + `Win32::System::Threading::GetCurrentProcess`, cast
  `&mut counters as *mut _ as *mut _`; fields `WorkingSetSize`, `PrivateUsage`.
- Plan review (2026-10-17) re-checked on docs.rs / registry source: `BackendSelector::renderer_name`
  and `require_wgpu_30(WGPUConfiguration)` exist in slint 1.18.1, and the winit backend accepts the
  names `"femtovg-wgpu"` (requires a WGPU30 request) and `"software"` (requires none);
  cosmic-text 0.19 `Buffer::new_empty(Metrics)`, `set_text(&mut self, &str, &Attrs, Shaping,
  Option<Align>)`, `shape_until_scroll(&mut self, &mut FontSystem, bool)`; unicode-width 0.2.2
  `UnicodeWidthChar::width` returns `None` only for control characters, ambiguous = 1.
- png 0.18: `Encoder::new(writer, w, h)`, `set_color(ColorType::Rgba)`, `set_depth(BitDepth::Eight)`,
  `write_header()?.write_image_data(&bytes)?`.

## Decisions taken by the planner (not the owner)

- Slint GPU renderer: **`renderer-femtovg-wgpu`**, not Skia (Skia pulls prebuilt binaries and a
  much larger binary; femtovg-wgpu imports wgpu textures, verified in its `images.rs`).
- "Software" means **no GPU at all**: Slint's software renderer (softbuffer) plus the CPU grid.
- The debug toggle switches only the **grid painter** live (GPU texture vs CPU buffer) while Slint
  stays on its renderer; Slint's renderer itself is chosen at start (`--renderer`, `FLARE_RENDERER`)
  because a Slint platform can be set once per process. Persisting the choice is Milestone 7.
- Cell metrics: `cell_w = round(advance)`, `cell_h = ceil(ascent + descent + leading)`,
  `baseline = round(leading/2 + ascent)`, font 13 px x scale (PT `TERM_BASE_FONT_PX = 13`,
  xterm `lineHeight 1`). Compared with PT by eye in the PR, tuned in M4 if needed.
- Bold uses bright colours for indices 0..7 (xterm 6 default `drawBoldTextInBrightColors: true`,
  PT does not override it).
- Box drawing comes from the font in M1 (PT runs xterm's DOM renderer, which also uses the font).
- Glyph atlas: one `Rgba8Unorm` 2048x2048 page, shelf packing, 1 px padding, cleared and refilled
  when full. Mask glyphs are stored as `(255,255,255,coverage)`, colour glyphs premultiplied.
- The app mark is Prism Terminal's two-shape mark as a placeholder (owner question below).
- Console subsystem in all M1 builds so logs and `--screenshot` output are visible
  (`windows_subsystem = "windows"` arrives with the installer in M9).

Formulas (`px = font_px(scale)`, `k = px / units_per_em`): `cell_w = max(1, round(advance*k))`;
`asc = ascent*k`, `desc = -descent*k` (descent is negative in font units), `lead = leading*k`;
`cell_h = max(1, ceil(asc + desc + lead))`; `baseline = round(lead/2 + asc)`;
`underline_h = max(1, round(scale))`; `underline_y = baseline + max(1, round((cell_h - baseline) * 0.4))`;
`padding = round(TERM_PADDING_LOGICAL * scale)`.

(saturating subtraction, then max 1). `cell_origin = (padding + col*cell_w, padding + row*cell_h)`.
Compute in `f32` and use `f32::round` (half away from zero, so `round(1.5) == 2`) and `f32::ceil`, then
cast to `u32`. The table below was re-derived by hand from these formulas; if a row fails, the code
is wrong, not the table.

## Task 6: Scene, the shared layout step (Haiku)

**Files:** `crates/flare-render/src/scene.rs`.

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]

```

Rules, per cell in row-major order:
1. Skip cells with `WIDE_SPACER` entirely.
2. `span = if WIDE { 2 } else { 1 }`; `(x, y) = cell_origin(col, row, m)`.
3. `fg = resolve_fg(p, cell.fg, BOLD)`, `bg = resolve_bg(p, cell.bg)`; if `INVERSE`, swap them.
4. If the cursor is visible and at this cell (or at the spacer this WIDE cell owns, `cursor.col == col + 1`):

5. Push a `RectFill { x, y, w: span*cell_w, h: cell_h, color: bg }` **only if `bg != p.bg`** (the clear colour

6. If `cell.ch != ' '` (or it has combining marks): push `GlyphDraw { key: GlyphKey { text: cell.cluster(), bold, italic }, pen_x: x, baseline_y: y + baseline, color: fg }`.
7. If `UNDERLINE`: push to `overlays` `RectFill { x, y: y + underline_y, w: span*cell_w, h: underline_h, color: fg }`.
`clear = p.bg`. Painting order on both painters: clear, rects, glyphs, overlays.

```rust
/// the prototype `scratchpad\proto\src\main.rs` lines 75-77.
pub fn headless_device() -> Result<(wgpu::Device, wgpu::Queue, wgpu::AdapterInfo), String>;
/// Copies a texture to tightly packed RGBA (handles the 256-byte row alignment) and waits.
pub fn read_texture(device: &wgpu::Device, queue: &wgpu::Queue, tex: &wgpu::Texture) -> Vec<u8>;
```

Design (must match the CPU painter): one render pass with `LoadOp::Clear(scene.clear)` (bytes / 255
as f64), then instanced quads. A uniform `viewport: vec2<f32>` maps pixels to NDC
(`x/w*2-1`, `1-y/h*2`). Rect instance `{ rect: [f32;4] (x,y,w,h px), color: [f32;4] }`, blend
`None` (replace). Glyph instance `{ dst: [f32;4] (x,y,w,h px), uv: [f32;2] atlas texel origin,
color: [f32;4], is_color: f32 }`; the fragment shader reads the atlas with `textureLoad` (no
sampler) at `uv + floor(frag_position.xy - dst.xy)`, outputs premultiplied
`mask: (color.rgb * a, a)`, `color glyph: texel`, blend `BlendState::PREMULTIPLIED_ALPHA_BLENDING`.
Glyph instance per `GlyphDraw` with slot `s`: `dst = (pen_x + s.left, baseline_y - s.top, s.w, s.h)`,
`uv = (s.x, s.y)`, `is_color = 1.0` when `s.color` (then `color` is ignored), exactly the CPU
painter's placement. Draws whose `get` is `Ok(None)` or `Err(TooLarge)` are skipped (TooLarge logs once).
Overlays are a second rect batch after glyphs. Atlas texture `Rgba8Unorm` 2048x2048, filled by
`queue.write_texture` from `atlas.take_uploads()` before the pass; when `get` returns `Err(Full)`
while building the instances, clear the atlas and rebuild this frame's instance list from scratch
once (earlier slots are invalid after a clear); if it is full again, keep the instances that got a
slot, skip the rest and `log::warn!`. Buffers grow by doubling. Use the API forms in
"Verified facts" (Option bind group layouts, `immediate_size: 0`, `multiview_mask: None`, `cache: None`,
`depth_slice: None`, `PollType::wait_indefinitely()`).

# Surfaces: build plan

Spec: `docs/superpowers/specs/2026-10-21-surfaces-design.md`. Owner approval: 2026-10-21 ("create a
plan ... then just go ahead and keep working through the night"). Issues: the `surfaces` label on
GitHub, epic linked from each.

## How the build runs

- One stage is one PR. PRs are STACKED (each branch starts from the one before), because most stages
  touch `app.slint`, `appctl.rs` and `window.rs`. Branches: `surfaces-<n>-<name>`.
- Nothing is merged without the owner's per-PR yes. Each PR is pushed once when its stage is done
  (each push starts a paid Windows CI run on this private repo; state the CI result in the merge ask).
- Gentle builds: at most 2 builders, `CARGO_BUILD_JOBS=6`, nextest `--test-threads 4`, idle priority,
  one Flare app at a time, GPU and WebView2 tests one at a time. Shared target dir
  `.claude/targets/t1`.
- Gates per stage, in the stage's worktree: `cargo fmt --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo nextest run --workspace` (full), `cargo deny check` when a
  dependency changed, the stage's e2e scenarios plus the existing ones that touch the same surfaces.
- Review per stage: an Opus reviewer reads the diff against the spec and the regression rules; its
  confirmed findings are fixed before the push.
- Docs per stage (required for the Prism Terminal port): update `docs/surfaces/` (protocol,
  decisions, lessons), `docs/features.md` (the decision, date, test) and README features.

## Stages

### 0. Docs (`surfaces-0-docs`)
Spec, this plan, `docs/surfaces/README.md` (index for the port), `lessons.md`, `decisions.md`.

### 1. Panels (`surfaces-1-panels`), issues: panel system, path preview
- `crates/flare-surfaces` (new, no Slint): panel model (kind, per-tab state, width fraction, stored
  atomically next to tabs), layout maths (slot rect from window size, min/max widths, DPI), the
  overlay/airspace decision.
- Slint: a panel slot right of the grid with a splitter; a panel header (title, close); native
  image viewer (fit, 1:1 on click, checkerboard for alpha) and text viewer (monospace, read-only,
  capped at 4 MB, unreadable answered with a reason).
- A left click on a path link that is an image or text file opens it in the tab's panel (setting
  "Open previews in Flare", default on). Folders and other files keep today's behaviour; runnable
  files are never opened (rule 14).
- Chord to toggle the panel and to move focus (decide; record in decisions.md; one keymap table).
- Tests: unit (model, layout, storage), ui_tests (open, close, splitter, focus, overlay flag), e2e
  `panelImage` (click a path, panel shows the image at 100% and 225%).

### 2. Control channel and agent tools (`surfaces-2-channel`), issues: control channel, MCP server
- `crates/flare-ctl`: protocol v1 types, framing, grants, client library. Server in Flare: named pipe
  per user (ACL), worker threads, answers via `UiMsg` to the UI thread, limits and timeouts.
- Methods: `hello`, `tabs.list`, `panel.open|close|state`, `view.image|file|text`.
- `crates/flare-mcp` binary: stdio MCP server (initialize, tools/list, tools/call), tab from
  `FLARE_TAB_ID`; tools `show_image`, `show_file`, `close_panel`. Shipped beside flare.exe (pack
  script), declared in the bundled `flare-status` plugin manifest.
- `docs/surfaces/protocol.md`: every method.
- Tests: protocol round trips, a refused grant, a malformed line closes one client, the MCP handshake
  against a fake channel, e2e `ctlChannel` (a real pipe to the real exe opens a panel).

### 3. Web panel (`surfaces-3-web`), issues: browser panel, video
- `crates/flare-web`: WebView2 environment and controller on the UI thread, child HWND positioned to
  the slot (physical pixels, DPI change, monitor move), profiles under `%LOCALAPPDATA%\Flare\WebView2`,
  runtime missing -> message panel. Hidden while an overlay is open, with a still in its place.
- Browser panel UI: address field, back, forward, reload, stop; the page title in the panel header.
- Channel: `browser.open|navigate`. MCP: `open_page`.
- Video plays in the panel (WebView2 does this; verify a local mp4 plays in the e2e).
- Tests: placement maths, e2e `webPanel` at 100% and 225% (child rect equals slot rect), overlay hides
  it, closing frees the controller.

### 4. Agent browser control (`surfaces-4-agent-browser`), issue: Claude drives the browser
- CDP over `CallDevToolsProtocolMethod`: screenshot (PNG, viewport, max 1600 px wide), snapshot
  (accessibility tree trimmed to interactive and text nodes, each with a ref; refs map to backend node
  ids and centres), click (ref or x,y), type (insertText), press (key events), scroll, wait (text,
  selector, ms; capped), navigate. `browser_eval` behind a setting, off.
- The "Claude is using this page" ribbon while a call runs.
- MCP: `browser_look` returns image content plus the element list; the other `browser_*` tools.
- Tests: snapshot trimming on fixtures, ref resolution, e2e `agentBrowser` (open a local test page,
  look, click a button by ref, read the changed text, type into a field).

### 5. Mini-apps and diagrams (`surfaces-5-apps`), issues: mini-apps, diagrams
- `view.html` (an HTML string or a file) served from a per-panel folder through a virtual host with a
  strict CSP, no network unless `allow_network`. `view.diagram` renders Mermaid with a bundled
  mermaid build (MIT, notices).
- MCP: `show_html`, `show_diagram`.
- Tests: CSP blocks a fetch, a diagram renders (DOM has an svg), e2e `miniApp`.

### 6. Conversation reader (`surfaces-6-convo`), issues: changes view, task panel
- `crates/flare-convo`: transcript path from session id and folder, tail reader on a worker (bounded,
  survives truncation), fold to a model (edits, tasks, named files).
- Native panels: Changes (file list, diff per edit), Tasks (the list with states).
- Channel `convo.state`; header buttons to open each panel for an agent tab.
- Tests: fold on recorded transcript fixtures (scrubbed), tail on growing file, ui_tests, e2e with a
  fake transcript.

### 7. Live preview and agent board (`surfaces-7-board`), issues: live web preview, agent board,
questions as notifications
- A `localhost` / `127.0.0.1` URL printed in a tab offers a Preview chip that opens the web panel.
- Board panel: every tab's agent, state, time, what it waits for; click to go there.
- A question from an agent in a hidden tab or an unfocused window shows a Windows notification
  (setting, default on), clicking it focuses that tab.

### 8. Mods (`surfaces-8-mods`), issue: mod system
- Manifest parse and validation, Settings > Mods (list, permissions, enable), tokens, the
  `window.flare` bridge in mod panels, mod tools routed through flare-mcp. A sample mod in
  `docs/surfaces/sample-mod/` (a notes panel the agent can append to).
- Tests: manifest errors, grant enforcement (a mod without `browser` is refused), e2e with the sample.

## Order and stopping

Stages run in order. If a stage hits a blocker, it is written in `docs/surfaces/lessons.md` and the
PR body, the PR is pushed as a draft, and the next stage that does not depend on it starts.
Dependencies: 2 needs 1; 3 needs 1; 4 needs 2 and 3; 5 needs 3; 6 needs 1; 7 needs 3 and 6; 8 needs
2 and 3.
